# CIP-0025: Paper author name redaction via front-matter extract

## Summary

Enable review flows to **extract title and authors** from typical academic paper PDFs, then **redact those author names** into a stored anonymised PDF for the current record.

**Architecture (accepted intent at Proposed):**

1. **Phase 1 — extract (lynguine access):** add a CIP-0013 aspect (working name `paper_frontmatter`) and compute helper parallel to `extract_form_fields` / `form_fields`.
2. **Phase 2 — redact (referia document ops):** consume editable author fields (and optional text spans / bboxes when available) to produce a redacted PDF via existing `editpdf` / prepare-and-store patterns.

Do **not** invent a parallel PDF parser in referia. Extend lynguine’s pluggable document layer; referia wires flows and redaction UX (progressive augmentation).

## Motivation

Reviewers often need a blind or anonymised reading copy of a paper. Today referia can copy PDFs, extract page ranges (`editpdf`), extract raw text (`pdf_extract_text`), and soft-fill structured fields from **form-like** PDFs (`extract_form_fields` → Panel candidate email). It cannot yet:

- pull **title + author list** from a typical academic first page into review columns, or
- turn that list into a **redacted PDF** without manual Acrobat / Preview work.

The extract step is the same *capability shape* as Panel form soft-fill: one structured record per document, strategy-selected, human-editable before downstream use. Redaction is the document-centric payoff.

**Tenet check**

| Tenet | Application |
|-------|-------------|
| Progressive augmentation | New aspect/engine in lynguine; referia consumes via compute + document ops |
| Explicit / implicit separation | Strategy id + recogniser score recorded; no silent “best guess” without provenance |
| Document-centric management | Redacted PDF is a first-class review document, not an external side quest |

### Phase 1: `paper_frontmatter` (lynguine)

Mirror the Panel `form_fields` slice:

| Piece | Panel analogue | Paper front matter |
|-------|----------------|--------------------|
| Aspect | `form_fields` | `paper_frontmatter` |
| Grain | one record / PDF | one record / PDF |
| Compute helper | `extract_form_fields` | `extract_paper_frontmatter` |
| Strategy (v1) | `cam_panel_application.v1` | e.g. `academic_paper_front.v1` |
| Recogniser | page-0 label boosts | Abstract/Introduction cues, arXiv stamp, title-like top block |

**v1 parsing approach (typical digital papers)**

1. Restrict to early pages (page 0, optionally page 1); stop region at Abstract / Introduction / Keywords when present.
2. Use reading order + block geometry (already on `Block`: bbox). Prefer top-of-page substantial text as title.
3. Treat following lines until affiliation / email / Abstract as author lines; split on commas, `and`, and common separators.
4. Emit structured fields; record `segment_strategy` and recogniser rationale like other aspects.

**v1 non-goals**

- Full publisher coverage (ACM/IEEE two-column edge cases, LNCS variants).
- Scanned PDFs / OCR (fail clearly via existing sparse-text policy).
- Parsing end-of-paper **References** (already `pmlr_references.v1`).

**Optional reader upgrade:** expose font size (or size relative to page median) on PDF blocks. Not required for a positional v1, but improves title detection; keep as an explicit follow-on under lynguine CIP-0013 if Phase 1 heuristics are insufficient on fixtures.

**Home for lynguine work:** backlog under **lynguine CIP-0013** (Accepted / In Progress) — same path as `form_fields` + `cam_panel_application.v1`. This referia CIP owns the end-to-end redaction outcome and the referia wiring; it does not fork CIP-0013.

### Phase 2: redaction (referia)

After authors are in the store (and optionally corrected):

1. **Input:** PDF path for the record + author name list (from columns or nested object field).
2. **Operation:** produce a redacted PDF under `storedirectory` (new interface key or an `editpdf`-adjacent prepare step). Prefer text-search redaction boxes when spans/bboxes exist; otherwise search page text for author string occurrences with conservative matching (whole-token, case-fold).
3. **Safety:** never claim success if zero matches and authors were non-empty — surface a warning so the reviewer knows the file may still identify authors (affiliations, emails, running headers).
4. **Scope control (config):** which fields to redact (authors only vs authors + emails); whether to blank first-page header region vs whole-document string search (v1: first N pages configurable, default 1–2).

Exact PDF library choice (PyMuPDF redaction annotations, pypdftk, …) is an implementation decision at Accepted → backlog time; prefer whatever already supports prepare/serve in the web path without a new hard dependency if possible.

### Flow sketch (referia `_referia.yml`)

Illustrative only — final keys chosen in backlog:

```yaml
compute:
  - field: paper
    function: extract_paper_frontmatter
    args:
      filename: "{pdf_name}"   # or path template
      strategy: auto           # or academic_paper_front.v1
  # soft-fill Title / Authors from paper.title / paper.authors
```

Redaction triggered by a prepare/download action (like `editpdf`) or an explicit compute that writes a path column for the viewer.

### Alternatives considered

| Approach | Why not (for now) |
|----------|-------------------|
| LLM-only title/author extract (CIP-0006) | Costly and less reproducible; keep as optional fallback after structured extract |
| GROBID / CERMINE as hard dependency | Heavy ops footprint; fine as a future named strategy, not v1 default |
| Referia-only regex on `pdf_extract_text` | Duplicates CIP-0013; breaks progressive augmentation |
| Redact without extract (manual name entry only) | Possible as a fallback UI, but misses the Panel-style convenience that motivates Phase 1 |

## Implementation Plan

1. **Accept design** — confirm aspect name, Phase 1 vs 2 sequencing, and that lynguine work stays under CIP-0013.
2. **Lynguine Phase 1** (after Accept; spawn lynguine backlog under CIP-0013):
   - Add `paper_frontmatter` aspect + engine/strategy `academic_paper_front.v1`.
   - Register `extract_paper_frontmatter` compute helper.
   - Synthetic fixtures (public-domain / generated papers; no PII in-repo) + unit tests.
3. **Referia wiring**:
   - Expose helper through referia Compute registry if not inherited automatically.
   - Example `_referia.yml` soft-fill for Title / Authors.
4. **Referia Phase 2 — redaction**:
   - Document op + web/notebook prepare path; store redacted PDF; serve in viewer.
   - Warnings when matches are incomplete.
5. **Validation** — fixture papers + one real local workflow (not committed) for smoke test.

## Backward Compatibility

- No change to existing `editpdf`, `pdf_extract_text`, or `extract_form_fields` behaviour.
- New aspect/helper and optional interface keys are opt-in.
- Flows that do not declare front-matter compute or redaction are unaffected.

## Testing Strategy

- **Lynguine:** fixture PDFs covering single-column PMLR/arXiv-like first pages; assert title/author fields; sparse-text → empty/error per policy; strategy auto vs manual.
- **Referia:** soft-fill into columns; edit authors; redact produces file; zero-match warning; viewer serves redacted path.
- **Regression:** existing Panel `form_fields` and `pmlr_references` tests remain green.
