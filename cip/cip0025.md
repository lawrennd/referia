## Summary

Deliver REQ-001A in review flows by composing:

1. **Optional term source — extract (lynguine CIP-0013):** `paper_frontmatter` / `extract_paper_frontmatter` → title + authors (+ optional emails) soft-filled into editable columns.
2. **Human stage (referia):** reviewer corrects or extends the term list (manual-only lists also satisfy REQ-001A).
3. **Apply (lynguine CIP-001A):** map columns → RedactTerms → `redact_pdf`; referia prepares/stores/serves like `editpdf`.

REQ-001A does **not** require author extract. Extract is a convenience HOW for populating terms. Manual term entry alone is a valid path.

Do **not** invent a parallel PDF parser or string-search stack in referia.

## Motivation

Reviewers need anonymised reading copies. Separating WHAT (redact from an explicit list) from HOW (where terms come from) keeps the requirement honest and lets mail-style or hand-edited term sources reuse the same apply path.

## Detailed Description

### Layering

```
┌─────────────────────────────────────────────────────────────┐
│ OPTIONAL: LYNGUINE CIP-0013 — term source                   │
│  paper_frontmatter → authors / emails → soft-fill columns   │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ REFERIA — editable RedactTerms (manual and/or soft-fill)    │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ LYNGUINE CIP-001A — redact_pdf(source, dest, terms, …)      │
└───────────────────────────┬─────────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ REFERIA — store / serve / surface zero-match warnings       │
└─────────────────────────────────────────────────────────────┘
```

### Phase A: apply wiring (satisfies REQ-001A)

First-class interface key **`redactpdf:`** (peer of `localpdf` / `editpdf`):

```yaml
redactpdf:
- sourcedirectory: ./files
  storedirectory: ./pdfs
  field: LocalDocumentLink
  terms_field: RedactTerms   # semicolon-separated; or terms: [...]
  name: redacted             # optional dest stub
  max_pages: 2               # optional
```

Prepare/serve mirrors `editpdf`: document panel **Prepare redacted view** →
`POST /redact-pdf/{n}` → `ensure_redact_pdf` → lynguine `redact_pdf(source, dest, terms)`.
Source under `sourcedirectory` is never modified; only `storedirectory` receives
the view copy. Zero-match warnings surface in the status bar. Do **not** use a
standalone pre-run script — preparation belongs in this path (or an equivalent
review `precompute` that calls the same ensure).

### Phase B: paper front-matter soft-fill (convenience HOW)

Consume lynguine `extract_paper_frontmatter`; soft-fill Authors (and optional emails) into the same term columns Phase A uses. Not required for REQ-001A acceptance if manual terms work end-to-end.

### Flow sketch

```yaml
compute:
  - field: paper
    function: extract_paper_frontmatter   # optional convenience
    args:
      filename: "{pdf_name}"
      strategy: auto
# soft-fill Authors from paper.authors; prepare → RedactTerms → redact_pdf
```

### Alternatives considered

| Approach | Why not |
|----------|---------|
| Make author extract part of REQ-001A | Mixes WHAT with a specific term source |
| Referia-owned PDF redaction engine | Duplicates lynguine CIP-001A |
| Single anonymise_paper(pdf) | Hides stages; blocks manual-only terms |
