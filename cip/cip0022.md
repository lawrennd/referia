## Summary

Add an opt-in **permalink** URL mode for `referia serve --root`. In that mode the server builds a permalink tree from markdown pages whose frontmatter says they are referia configs (`layout: referia` plus `permalink:`). The live URL is that permalink, not the filesystem path of a `_referia.yml`. Page files are ordinary Jekyll names at the study root (`index.md` for the hub, `01_turns.md` for a stage). They are not called `referia.md`. Path mode (CIP-000C) stays the default for thesis trees.

This CIP addresses REQ-0019. REQ-0009 path hosting stays.

## Motivation

`_referia.yml` meant “config, not a page.” DODS stages now have a public markdown body and a Jekyll `_config.yml` (`ghub`, `layout`). Jekyll skips underscore files. Calling the page `referia.md` still brands the site after the tool and still defaults to `/01_turns/referia.html`.

Giki pages declare `layout:` and `permalink:`. The study pages should do the same. Referia must then **build the permalink tree** instead of mapping `/01_turns/` onto `01_turns/_referia.md`. That mapping is a server mode, because OneDrive thesis reviews still want path URLs.

## Detailed Description

### Two URL modes

| Mode | How a URL finds a config | Who it is for |
|------|--------------------------|---------------|
| **path** (default, CIP-000C) | `/theses/examined/introduction/` → that directory’s `_referia.md` / `_referia.yml` | Existing review trees |
| **permalink** | `/01_turns/` → the markdown file whose YAML `permalink` is `/01_turns/` | Jekyll study repos |

The review **directory** is the folder that contains the markdown file. For a top-level study page that is the serve root, so stage-local stores (`parameters.yml`, caches) keep a sibling folder named after the stem (`01_turns/parameters.yml`) and YAML says `directory: 01_turns`. Shared stores use `directory: info`. Permalink is the public identity only.

### How a file counts as a config in permalink mode

A file is a referia config when **all** of these hold:

1. It is markdown (`.md`) under the serve root, not excluded by site `_config.yml` `exclude`
2. Frontmatter has `layout: referia` (Jekyll layout name; this is the type marker, not the filename)
3. Frontmatter has `referia_config_version` (so a themed stub without a pipeline is not loaded as a reviewer)
4. Frontmatter has `permalink`

`layout: referia` is the Jekyll hook. The filename is `index.md` (or another content name). Do not discover `referia.md` / `_referia.md` as the preferred public name in this mode. Path mode keeps today’s `_referia.md` then `_referia.yml` preference.

### Where the mode is set

Site `_config.yml` at the serve root (already loaded for `ghub`) grows a referia block:

```yaml
title: "AI dialogue formats — chatbot vs workshop"
github_username: mlatcl
ghub:
  edit: true
  organization: mlatcl
  repository: dods-ai-dialogue
  branch: main
referia:
  urls: permalink   # path | permalink; default path
```

`referia serve --root .` reads that. CLI override for one-off runs:

```bash
referia serve --root . --urls permalink
```

`--urls path` forces path mode even if `_config.yml` says permalink. Missing `referia.urls` means **path**, so OneDrive roots do not change behaviour.

Do not make permalink the global default. Thesis `_referia.yml` files have no `permalink` and no Jekyll layout.

### Building the tree

On startup, and again when a watched config’s mtime changes enough to miss the index:

1. Walk markdown under `--root` (CIP-000E: stay inside the jail; honour `exclude`)
2. Parse frontmatter only (`read_config_mapping`)
3. Keep files that match the four rules above
4. Normalise permalink: leading slash, trailing slash (`/01_turns/` and `/01_turns` are one key)
5. Insert into `permalink → {config_file, user_file, directory}`
6. Duplicate permalinks are a **startup error** (log both files; do not serve a silent winner)

The catch-all route `{config_path:path}` looks up that map **before** the directory `_resolve_config_path` fallback. A miss is 404, not “no `_referia.yml` in this folder.”

Root permalink `/` is the hub `index.md` at the study root. Stage pages are siblings: `01_turns.md`, `01_chunk.md`, `siding_kind.md`. That replaces “directory `01_turns/` contains `_referia.md`.”

Edit-on-GitHub still uses the **source** relative path (`01_turns.md`), which is Jekyll’s `page.path`. The header URL is `ghub` + that source path. Do not put the permalink into the GitHub edit URL.

### Example stage file

`01_turns.md` (study root):

```yaml
---
layout: referia
permalink: /01_turns/
referia_config_version: 2
title: "AI dialogue formats — labelled speaker turns"
display:
  layout: side_by_side
parameters:
  type: yaml
  directory: 01_turns
  filename: parameters.yml
  index: index
  select: dialogue-v1
# input / output / review …
---
```

Jekyll: `layout` wraps `{{ content }}`; `permalink` is `/01_turns/`. Referia: same permalink; widgets from `review:`; stores relative to the study root (`01_turns/parameters.yml`, `info/turns.yml`).

Hub glob becomes sibling `01_*.md` / `siding_*.md` pages. A listing row’s `config_url` is the permalink.

### What we are not doing

- Rendering widgets in Jekyll
- Requiring a Jekyll build to serve
- Renaming thesis `_referia.yml` trees
- Allowing a permalink that escapes `--root` (URL is not a filesystem path; the resolved file must still sit under the jail)
- Using frontmatter key `path:` — Jekyll reserves `page.path` for the source file

### Alternatives rejected

| Idea | Why not |
|------|---------|
| Keep `_referia.md` + Jekyll `include:` | Fights Jekyll’s underscore rule; still tool-branded |
| Rename to `referia.md` | Public URL `/01_turns/referia.html`; site named after the runtime |
| Infer URL from directory only, add `layout:` | Jekyll and referia still disagree when permalinks are pretty or files are `index.md` |
| Always-on permalink index | Breaks REQ-0009 thesis trees that have no permalink |

## Implementation Plan

1. **Site config** — Read `referia.urls` from `_config.yml` in `referia.config.site`; default `path`.
2. **CLI** — `referia serve --urls {path,permalink}` overrides the site file when given.
3. **Tree builder** — Module that walks markdown, filters by `layout` + `referia_config_version` + `permalink`, errors on duplicates.
4. **Router** — In permalink mode, resolve `{config_path}` via the tree; keep path-mode `_resolve_config_path` unchanged.
5. **Discovery / check / migrate** — Permalinks mode lists tree keys; `referia check` reports missing permalink / duplicate / not-a-config markdown.
6. **Study files (dods-ai-dialogue, after Accept)** — `git mv` hub `_referia.md` → `index.md` and each `01_turns/_referia.md` → `01_turns.md` at the study root; add `layout` + `permalink`; point stage-local stores at the leftover data folder; hub lists permalinks; `_config.yml` sets `referia.urls: permalink`.

## Backward Compatibility

Path mode is the default. No change to `_referia.yml` reviews, CIP-0010 catalogs, or OneDrive URL paths unless that root’s `_config.yml` sets `referia.urls: permalink`.

Markdown studies that still use `_referia.md` without a permalink keep working in path mode.

## Testing Strategy

- Unit: permalink normalisation, duplicate detection, exclude honouring, jail
- Unit: `layout: referia` without `referia_config_version` is not a config
- App: `--urls permalink` maps `/01_turns/` to `01_turns.md`; `/01_turns/referia.md` 404s
- App: default `--root` of a fixture with only `_referia.yml` still uses path URLs
- Regression: CIP-000E path tests; CIP-0010 hub still lists path configs in path mode
