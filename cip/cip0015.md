# CIP-0015: Stateless phrase-extract, embed, and grain-seed compute

> **Note**: CIPs describe HOW to achieve requirements (WHAT).

## Summary

Register three referia compute functions so dialogue configs can extract phrases, embed them, and seed k=1 soft MPPCA — all **pure** field-in / field-out callables. Prompts and models come from constants; an LLM client is an injected argument, not `self.interface`. Results land in named cache or output columns. No jsonl checkpoint directory, no sidecar `.npy`, no `build_records.py` as the Assess bake.

**Pack** (tall phrase table → one corpus row of arrays) is Access IO in lynguine [CIP-0014](https://github.com/lawrennd/lynguine/blob/main/cip/cip0014.md), not this CIP.

Addresses [REQ-0010](../requirements/req0010_dialogue-pipeline-in-referia.md) (steps 4–5 and 7) and the Assess half of the bake debt in [CIP-0012](./cip0012.md).

## Motivation

pub-dialogue and ai-dialogue-formats extract short concern / benefit / condition phrases with an LLM, then embed those phrases. Referia has `llm_extract` (free-text string) and no embedding compute. The subject-grain example bakes phrases, embeddings, and the k=1 fit in `examples/subject_grain_uq/build_records.py`, which writes YAML by hand and calls the OpenAI SDK outside `LLMManager`.

That is the sidecar pattern REQ-0010 forbids. Grain Assess already consumes `records.yml` / `scores.yml`; extract, embed, and seed fit should be ordinary compute declared in `_referia.yml`. Packing the tall phrase table is a grain change — lynguine reshape, same family as explode.

## Detailed Description

### Stateless contract

Every function is `(row fields, parameters, constants, client?) -> fields`. It does not own files or keep process-global result dicts. It is **not** a nested closure on `Compute` that reads `self.interface`.

An LLM client diskcache for API cost may remain inside `LLMManager`. It is not the analysis store. Phrase text and embedding vectors must be written to cache or output columns so a later config can load them without calling the client.

Undeclared sidecar files (`checkpoints/`, `extracted_*.json`, `embeddings_*.npy`) are a spec violation.

### Cache vs output (do not double-write)

Named `cache:` is for **regenerable intermediates whose recompute is expensive**. It is not a second copy of output.

| Artefact | Store | Why |
|----------|--------|-----|
| LLM `extraction_payload` | **cache** (compressed YAML) | Re-calling the model costs money; payload is not the downstream grain |
| `extraction_phrases` list | in-memory for explode only | Do **not** persist this list in cache once `phrases.yml` exists |
| Phrase rows + `embedding` | **output** `phrases.yml.gz` | Later configs and pack need them; embeddings as YAML floats are bulky |
| Packed arrays | **output** `records.yml.gz` (lynguine CIP-0014 pack) | Grain/distance input |
| Chunk `units` list | optional cache | PDF segment is local; once `chunks.yml` exists the cache may be deleted |
| LLMManager diskcache | not a named store | API cost only; referia CIP-0017 must label it separately |

On-disk gzip for YAML is lynguine [CIP-0015](https://github.com/lawrennd/lynguine/blob/main/cip/cip0015.md) (`filename: phrases.yml.gz`, still `type: yaml`). Numeric-heavy **output** (embeddings, packed arrays, R, EMD) should use the same named-store contract with `type: parquet` once that phase lands — not an undeclared `.npy` beside YAML. Review-facing cache date/size/columns is referia [CIP-0017](./cip0017.md).

### Vongole-shaped modules (do not grow `__init__.py`)

Live inheritance is `lynguine.Compute` → `referia.Compute`. lynguine [CIP-0007](https://github.com/lawrennd/lynguine/blob/main/cip/cip0007.md) (Proposed) inserts vongole in the middle and retargets generic `llm_*` there — **not** lynguine.

Implement as module-level pure functions, thin registry names only:

```
referia/assess/compute/phrases.py   # llm_extract_phrases
referia/assess/compute/embed.py     # llm_embed
referia/assess/compute/mppca.py     # subject_grain_seed_fit (existing file)
```

Later transfer test: `from vongole.functions.embed import llm_embed` with the YAML `function:` name unchanged. Do not copy the CIP-0006 nested-closure pattern used by `llm_complete` / `llm_pdf_review`.

Inject the LLM/embed client as an argument (or a small protocol). Review-domain `llm_pdf_review` / `llm_custom_query` stay methods/closures in referia.

### Functions

**`llm_extract_phrases`** (row-local)

- Reads: chunk `text` (and optional `context` / `extract_text`).
- Constants: prompt template, sentinel (`NO_CONCERN` / `NO_BENEFIT` / `NO_CONDITION`), model, `kind`, `min_words`, `max_words`, `max_items`.
- Writes: cache field `extraction_payload` (raw structured reply) on the chunk row, plus `extraction_phrases` (list of dicts). The config then uses lynguine `output.explode` to phrase rows (`phrase`, `kind`, `chunk_id`, `doc_id`, optional `quote`).
- Drop rules (word-count bounds, sentinel, optional quote threshold) are parameters, not hidden code.
- Does not replace `llm_extract`; that free-text helper stays for review comments.

**`llm_embed`** (row-local)

- Reads: `phrase` (or a configured text field).
- Constants: embedding model, optional `pca_dim`.
- Writes: `embedding` (list of floats, L2-normalised; PCA-reduced if `pca_dim` is set) on the same row.
- Batching is an implementation detail inside one call; it must not require a module-level queue that survives across rows as analysis state.

**`subject_grain_seed_fit`** (row-local on the **packed** corpus row)

- Reads: `embeddings` (and `phrases` for naming) already packed as cell arrays by CIP-0014.
- Parameters: `sigma2`, `sigma2_mode` (`fixed` | `profile`), `k` default 1, `em_accept`.
- Writes: `responsibilities`, `uq_by_topic`, `topic_keys`, provisional `topic_labels` / `topic_parent` / `topic_tree`.
- Reuses `referia.assess.compute.mppca.mppca_fit`. Replaces the Assess half of `build_records.py`.
- Idempotent if catalogue fields already exist and a `force_refit` parameter is false — the skip is a field check, not a hidden checkpoint.

### Config shape (02_embed + 03_grain seed)

`02_embed` input is `chunks.yml`. PopulateButton extract writes **cache** `extraction_payload` (and in-memory `extraction_phrases` for explode). `output.explode` writes `phrases.yml.gz`. PopulateButton embed writes `embedding` on the phrase row. lynguine `pack` writes `records.yml.gz`.

`03_grain` input is `records.yml`. Review `precompute` calls `subject_grain_seed_fit` when `responsibilities` is empty. Propose / Confirm / Undo stay existing `subject_grain_*` functions.

Prompts and models live in `constants:` / `global_consts:`, not in Python.

### Non-goals

- Framing lenses, quote-verification UI, or StageRunner fingerprints as the source of truth.
- Changing the Propose / Confirm / Undo UX (CIP-0012 non-goal).
- Merge (deferred REQ-0010 follow-on).
- Pack / explode / file catalog (lynguine CIP-0014).
- Promoting these functions to **lynguine**. Generic extract/embed/seed are vongole-shaped; they stay in referia until CIP-0007 is Accepted.
- Rewriting existing `llm_complete` closures (CIP-0007 cleanup).
- Gzip IO (lynguine CIP-0015) or cache-status UI (referia CIP-0017).

## Implementation Plan

1. **Modules and signatures** — add the three functions as pure callables; registry is a name map. Prompts and models required from config / row. Client injected.
2. **Extract** — structured parse (`phrase || quote` or JSON), sentinel, list of phrase dicts for explode.
3. **Embed** — embeddings API on the injected client (add to `LLMManager` if missing); L2; optional PCA; write list column.
4. **Seed fit** — wrap `mppca_fit` + `rebuild_uq_by_topic`; retire Assess writes from `build_records.py`. Pack of `records.yml` waits on lynguine CIP-0014.
5. **Draft configs** — `02_embed` and `03_grain`; retarget subject_grain_uq bake Assess half to this CIP.

## Backward Compatibility

- `llm_extract` unchanged.
- Existing `subject_grain_uq` keeps working if `records.yml` / `scores.yml` are already present.
- `build_records.py` remains until pack (CIP-0014) and seed fit land, then becomes a thin wrapper or is deleted (CIP-0012 remaining work).

## Testing Strategy

- Unit tests: parse sentinels and drop rules; embed writes L2 unit vectors with a fake client; seed fit k=1 produces one topic key and R rows summing to 1.
- No live API in CI (`stub` / fake embedder).
- Manual: draft `02_embed` then `03_grain` against a tiny synthetic phrase table (hand-packed `records.yml` until CIP-0014 pack exists).
