# CIP-0008: Conversational Context for LLM Functions

## Status

**Proposed** - Initial design complete, ready for implementation

## Description

Enable LLM functions to include previous conversation history as context when generating responses. This allows for true conversational interactions where the LLM can build on previous questions and answers, reference earlier discussions, and maintain context across multiple queries.

This feature builds on CIP-0007 (Append Mode) by allowing accumulated conversation history to be fed back into subsequent LLM queries as context.

## Motivation

### Current Limitation

Currently, each LLM query operates in isolation:
1. User asks: "What are the main contributions?"
2. LLM responds based only on the PDF text
3. User asks: "How does the second contribution relate to prior work?"
4. LLM has no memory of the first question or its own previous response

This forces users to either:
- Repeat context in every question
- Manually copy/paste previous responses
- Ask questions in a single, complex prompt

### Desired Behavior

With conversation history:
1. User asks: "What are the main contributions?"
2. LLM responds (stored in field with append mode)
3. User checks "Include conversation history" checkbox
4. User asks: "How does the second contribution relate to prior work?"
5. LLM sees: PDF text + previous Q&A + current question
6. LLM can reference "the second contribution" from previous conversation

### Use Cases

1. **Iterative analysis**: Build understanding through multiple questions
2. **Follow-up questions**: Ask clarifying questions that reference previous answers
3. **Avoiding repetition**: Don't re-ask for context the LLM already provided
4. **Multi-source context**: Include summary + questions + custom queries as context
5. **Conversation synthesis**: LLM can identify patterns across multiple exchanges

**Option 1: Same field (self-referential)**

### Token Limit Management

To prevent exceeding LLM context limits:

```python
def truncate_history_if_needed(history_text, max_tokens=4000):
    """
    Keep only recent conversation if history gets too long.
    
    Strategy:
    1. Count approximate tokens (words * 1.3)
    2. If over limit, keep only last N entries
    3. Add note: "[Earlier conversation truncated...]"
    """
    if not history_text:
        return ""
    
    # Simple token approximation
    approx_tokens = len(history_text.split()) * 1.3
    
    if approx_tokens <= max_tokens:
        return history_text
    
    # Split by separator and keep last N entries
    entries = history_text.split("\n\n---\n\n")
    
    # Keep last 5 entries (or whatever fits)
    kept_entries = []
    current_tokens = 0
    
    for entry in reversed(entries):
        entry_tokens = len(entry.split()) * 1.3
        if current_tokens + entry_tokens > max_tokens:
            break
        kept_entries.insert(0, entry)
        current_tokens += entry_tokens
    
    truncated = "\n\n---\n\n".join(kept_entries)
    return f"[Earlier conversation truncated for length]\n\n{truncated}"
```

## Risks and Considerations

1. **Token limits**: Long conversations may exceed LLM context windows
   - Mitigation: Implement truncation and provide token warnings
   
2. **Cost**: Including history increases token usage and API costs
   - Mitigation: Make it opt-in with checkbox, truncate old history
   
3. **Context confusion**: LLM might reference wrong parts of history
   - Mitigation: Clear formatting with headers, limit history length

4. **Performance**: Reading large history fields might be slow
   - Mitigation: Use field caching, truncate before passing to LLM
