# CIP-0016: Document-level EMD Address compute and Plotly visualisations

## Summary

Port document-level Earth Mover's Distance, classical MDS, and PERMANOVA / PERMDISP from multilogue into referia compute as **pure functions**, and add Plotly figure builders that CIP-0011 `PlotlyFigure` can bind. After lynguine CIP-0014 pack, histograms / EMD / MDS are **row-local** on the packed corpus + scores row (arrays already in cells). POT is an optional extra on the Assess package (`referia[distance]` today; `vongole[distance]` after CIP-0007). Plotly specs stay in referia.

Addresses [REQ-0010](../requirements/req0010_dialogue-pipeline-in-referia.md) steps 9–11.

## Motivation

After subject grain, the studies ask which documents raise which topics. multilogue `distance.py` builds a document-by-topic histogram P from soft responsibilities, uses cosine distance between topic means as the ground cost, computes pairwise EMD (`ot.emd2`), embeds documents with classical MDS, and tests group differences with PERMANOVA / PERMDISP. Visualisations live in `multilogue.viz` as matplotlib.

Referia has none of this. The grain example has no document identity. Putting the maths in referia compute (vongole-shaped modules; CIP-0006 referia-first, CIP-0007 generic Assess → vongole) lets `04_distance/_referia.yml` Address without importing multilogue at runtime.

## Detailed Description

### Stateless contract

Do **not** invent a second “table-level compute” mode. After pack, `embeddings`, `doc_ids`, and `responsibilities` are cell values on one corpus / scores row — the same grain as `subject_grain_seed_fit`.

- Histograms, topic means, EMD, MDS, and tests are `(arrays, parameters) -> fields` on that row.
- Group labels join on `doc_id` from `documents.yml` — Access join, not compute.
- Visualisation builders are `(arrays, labels) -> Plotly spec` and write figure JSON (or geometry; CIP-0012) to output fields. They live in `referia.util.plotly_figures` (viewer stack) and stay in referia when maths moves to vongole.
- Click bindings write `selected_doc` to output via existing CIP-0011 `on.click_point`.

No `document_distance_*.npy` sidecars. Constants (`min_mass`, `n_perm`, `seed`, group field name) come from `_referia.yml`. Matrices in YAML should use gzip (lynguine CIP-0015, `document_distance.yml.gz`); still `type: yaml`.

Implement maths in `referia/assess/compute/distance.py` as module-level functions; registry is a name map. Transfer test later: `from vongole.functions.distance import emd_distance_matrix` with YAML `function:` names unchanged.

### Compute functions (registry)

Port behaviour from [multilogue/distance.py](https://github.com/mlatcl/multilogue/blob/main/multilogue/distance.py), not a verbatim copy of notebook cells.

**`document_soft_topic_distributions`**

- Reads: `doc_ids` (length n phrases) and `responsibilities` (n × k).
- Parameters: `min_mass` (default 50).
- Writes: `P` (n_docs × k, row-stochastic), `doc_ids_kept`, `doc_mass`.

**`topic_means_from_responsibilities`**

- Reads: `embeddings` (n × d) and `responsibilities`.
- Writes: `topic_means` (k × d), L2-normalised. Ground cost input.

**`cosine_ground_cost`**

- Reads: `topic_means`.
- Writes: `ground_cost` (k × k), zero diagonal, clipped to ≥ 0.

**`emd_distance_matrix`**

- Reads: `P`, `ground_cost`.
- Writes: `emd_matrix` (n_docs × n_docs). Requires `pot`; raise a clear ImportError naming the Assess extra (`referia[distance]` today).

**`classical_mds`**

- Reads: `emd_matrix`.
- Parameters: `n_components` (default 2).
- Writes: `mds_coords`, `mds_explained`, `mds_negative_ratio`.

**`permanova` / `permdisp` / `axis_correlates`**

- Read `emd_matrix` or `mds_coords` plus a group label per kept document (from input metadata joined on `doc_id`).
- Constants: `n_perm`, `seed`, group field.
- Write dict/JSON-serialisable results to `permanova`, `permdisp`, `axis_correlates`, plus a Markdown field `distance_tests_md` for the review pane.

A façade **`run_document_distance_analysis`** may chain the above for a PopulateButton, still writing the same columns (no private return-only state).

### Plotly builders (`referia.util.plotly_figures`)

CIP-0011 viewer contract: specs with `customdata` for clicks.

- `doc_mds_plotly_spec` — scatter of MDS coords, colour by group; `customdata.doc` for `selected_doc`.
- `topic_document_heatmap_spec` — heatmap of P (documents × topics), topic labels from grain `topic_labels`.
- `emd_heatmap_spec` — pairwise EMD.
- `axis_correlate_bars_spec` — Pearson correlation of MDS axes with topic shares.

Do not grow Plotly knowledge inside `mppca.py` (CIP-0012).

### Config shape (`04_distance`)

Input: phrase or records store plus `scores.yml` (R, labels) plus document metadata (group). Output: `document_distance.yml` with the columns above and figure specs. Viewer: MDS `PlotlyFigure` + heatmap; review: group parameter, `distance_tests_md`, selected-document topic profile (Liquid over `P` row).

### Dependency

Optional extra on the **Assess package**: `referia[distance]` → `pot` today. After lynguine CIP-0007, the same extra moves with the maths as `vongole[distance]`. Core install must not require POT; EMD functions fail with an install hint naming the extra. Plotly builders are not part of that extra.

### Non-goals

- Lens-run σ² EMD (deferred step 15).
- Soft-histogram vs hard-count sensitivity UI (hard path can wait; default is soft R).
- Matplotlib exports; Plotly specs are the referia viewer payload.
- Merging documents into the grain plane (document identity stays an array on the corpus row / phrase table).

## Implementation Plan

1. Add Assess-package extra `referia[distance]` and a `_require_ot` helper (name the extra, not a sidecar path).
2. Port distribution / cost / EMD / MDS / tests as pure functions in `compute/distance.py`; thin registry map.
3. Add Plotly builders in `referia.util.plotly_figures` and tests with tiny synthetic P and means (no POT in unit tests that can use a stub distance matrix).
4. Wire `04_distance/_referia.yml` figure_source and click_point; group labels via Access join on `doc_id`.

## Backward Compatibility

New compute and optional extra only. Grain example unchanged. No change to CIP-0011 bindings.

## Testing Strategy

- Unit tests without POT: histograms, cosine cost, MDS on a hand-built D, PERMANOVA permutation count on a tiny matrix.
- Optional POT test marked skip if `pot` is absent.
- Plotly spec tests: keys, customdata alignment with `doc_ids_kept`.
- Manual: draft `04_distance` against synthetic scores from `03_grain`.
