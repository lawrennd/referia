## Summary

`referia.assess` sits at about **51%** branch coverage under the full unit
suite. Soft-MPPCA naming and web review paths are in reasonable shape; the
holes are the core Assess dataframe and Jupyter reviewer stacks
(`data.py`, `review.py`, `review_new.py`) plus the large LLM registry in
`compute/__init__.py`. This CIP defines a phased plan to close those gaps
with focused unit tests before adding more Assess behaviour.

**Baseline (2026-10-19, `coverage run --branch --source=referia` + full
`tests/`, excluding integration):**

| Module | Stmts | Cover |
|--------|------:|------:|
| `assess/data.py` | 705 | **18%** |
| `assess/review_new.py` | 574 | **13%** |
| `assess/review.py` | 583 | **41%** |
| `assess/compute/__init__.py` | 259 | **42%** |
| `assess/web_review.py` | 980 | 74% |
| `assess/compute/mppca.py` | 646 | 76% |
| `assess/compute/topic_naming.py` | 176 | 83% |
| `assess/viewer_bindings.py` | 266 | 93% |
| **`referia.assess` total** | **4189** | **51%** |

## Motivation

CIP-0017 / CIP-0012 work tightened naming and packaging, but CI and local
reports still show Assess as the weak package. Untested paths in
`CustomDataFrame` (`_finalize_df`, mapping augmentation, index /
subseries) and `Reviewer` (document creation, loop expansion,
`value_updated`) are exactly where regressions hide when lynguine or web
Reviewer behaviour changes. Raising coverage here is cheaper than
rediscovering those bugs in demos.

## Detailed Description

### Priority order (by miss mass and product risk)

1. **`data.py` (~18%)** — largest miss count; owns Access→Assess mapping,
   `set_index` / precompute triggers, column ops used by web and Jupyter.
   Hotspots: `_finalize_df`, `_augment_data`, `_augment_global_consts`,
   `set_index`, `add_column`, `automapping`.
2. **`review.py` (~41%)** — live Jupyter Reviewer. Hotspots:
   `extract_review` / `extract_widget`, `expand_loop_review`,
   `create_document`, `value_updated`, `populate_display`,
   `load_flows` / `template_to_value`.
3. **`compute/__init__.py` (~42%)** — soft-MPPCA naming helpers are largely
   covered; the hole is `_llm_functions_list` and prep helpers
   (`preprocess`, `prep_all`). Prefer registry smoke tests with stubbed
   LLM over live API calls.
4. **`review_new.py` (~13%)** — parallel Reviewer. Decide first:
   - **Cover** if it remains a supported entry point, or
   - **Delete / fold** into `review.py` if it is a stale fork (CIP
     follow-on). Do not invest deep tests in a module marked for removal.

`web_review.py` / `mppca.py` / `topic_naming.py` / `viewer_bindings.py` are
secondary: keep coverage from regressing; only add tests when new Assess
behaviour lands.

### Approach

- Prefer **unit tests with fixtures / mocks** over full from_flow demos.
- Reuse patterns from `tests/test_from_flow_mapping_timing.py`,
  `tests/test_global_consts.py`, `tests/test_conditional_visibility.py`,
  and `tests/test_compute_mppca.py` (stub LLM).
- Measure progress with:

  ```bash
  poetry run coverage run --branch --source=referia -m pytest tests/ -q
  poetry run coverage report --include='referia/assess/*'
  ```

- Targets (branch coverage, same command):
  - Phase 1: `data.py` ≥ **50%**
  - Phase 2: `review.py` ≥ **60%**
  - Phase 3: `compute/__init__.py` ≥ **65%** (or document intentional
    LLM-registry deferral)
  - Package: `referia.assess` ≥ **65%**
  - No regression below current % on already-strong modules

### Non-goals

- Full branch coverage of every LLM vendor branch.
- Integration / live OpenAI tests in CI.
- Rewriting Assess APIs (that belongs in CIP-0012 / other design CIPs).

## Implementation Plan

1. Accept this CIP → create backlog tasks (one per phase below).
2. **Phase A — `data.py`:** `_finalize_df` / augment / `set_index` /
   column helpers with synthetic frames and interface stubs.
3. **Phase B — `review.py`:** widget extract, loop expand, visibility,
   document/summary paths with MagicMock widgets / liquid.
4. **Phase C — `compute` registry:** stubbed `_llm_functions_list` entries
   and prep helpers; leave live naming under existing mppca tests.
5. **Phase D — `review_new.py`:** triage (cover vs remove); only then test.
6. Re-run package report; update this CIP with final numbers; close.

## Backward Compatibility

Tests only. No runtime API change.

## Testing Strategy

- New / extended files under `tests/` (prefer
  `tests/test_assess_data.py`, `tests/test_assess_review.py` extensions
  rather than one mega-file).
- Gate merges that touch `referia/assess/` on no coverage drop for the
  touched file (local or CI `--cov-fail-under` later if desired).
