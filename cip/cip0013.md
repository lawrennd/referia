## Summary

`referia.assess` sits at about **51%** branch coverage under `tests/` alone,
and about **57%** when `referia/tests/` is included (where most legacy Assess
unit tests live). Soft-MPPCA naming and web review paths are in reasonable
shape; the holes are the core Assess dataframe and Jupyter reviewer stacks
(`data.py`, `review.py`, `review_new.py`) plus prep helpers in
`compute/__init__.py`. This CIP defines a phased plan to close those gaps
with focused unit tests before adding more Assess behaviour.

**Baseline (2026-10-19, `coverage run --branch --source=referia`):**

| Suite | `data.py` | `review.py` | `compute/__init__` | `review_new.py` | Package |
|-------|----------:|------------:|-------------------:|----------------:|--------:|
| `tests/` only | 18% | 41% | 42% | 13% | **51%** |
| `tests/` + `referia/tests/` | 29% | 53% | 72% | 13% | **57%** |

**Result (2026-10-19, both trees + new coverage tests, 922 passed):**

| Module | Branch cover | Target | Status |
|--------|-------------:|-------:|:------:|
| `data.py` | **51%** | ≥50% | met |
| `review.py` | **68%** | ≥60% | met |
| `compute/__init__.py` | **84%** | ≥65% | met |
| Package (excl. `review_new`) | **71%** | ≥65% | met |
| Package (incl. `review_new`) | 63% | — | `review_new` deferred |

Measurement for this CIP uses **both** trees (`tests/` and `referia/tests/`),
and `pyproject.toml` `testpaths` is updated so bare `pytest` matches CI.

## Motivation

CIP-0017 / CIP-0012 work tightened naming and packaging, but CI and local
reports still show Assess as the weak package. Untested paths in
`CustomDataFrame` (`_finalize_df`, mapping augmentation, index /
subseries) and `Reviewer` (document creation, loop expansion,
`value_updated`) are exactly where regressions hide when lynguine or web
Reviewer behaviour changes. Raising coverage here is cheaper than
rediscovering those bugs in demos.

## Detailed Description

### Priority order (by miss mass and product risk)

1. **`data.py`** — largest miss count; owns Access→Assess mapping,
   `set_index` / precompute triggers, column ops used by web and Jupyter.
   Hotspots: `_finalize_df`, `_augment_data`, `_augment_global_consts`,
   `set_index`, `add_column`, `automapping`.
2. **`review.py`** — live Jupyter Reviewer. Hotspots:
   `extract_review` / `extract_widget`, `expand_loop_review`,
   `create_document`, `value_updated`, `populate_display`,
   `load_flows` / `template_to_value`.
3. **`compute/__init__.py`** — with `referia/tests/` already ~72%; fill
   `prep_all` / `preprocess` / registry smoke. Prefer stubbed LLM over
   live API calls.
4. **`review_new.py` (~13%)** — parallel Reviewer fork. **Triage (Phase D):**
   keep as a lightly-touched parallel entry (create_viewer dispatch only);
   do **not** invest deep coverage. Candidate for fold/delete in a follow-on
   CIP. Package target treats `review_new` as deferred debt.

`web_review.py` / `mppca.py` / `topic_naming.py` / `viewer_bindings.py` are
secondary: keep coverage from regressing; only add tests when new Assess
behaviour lands.

### Approach

- Prefer **unit tests with fixtures / mocks** over full from_flow demos.
- New coverage tests live under `tests/` (discoverable with `referia/tests/`).
- Measure progress with:

  ```bash
  poetry run coverage run --branch --source=referia -m pytest tests/ referia/tests/ -q
  poetry run coverage report --include='referia/assess/*'
  ```

- Targets (branch coverage, both test trees):
  - Phase A: `data.py` ≥ **50%**
  - Phase B: `review.py` ≥ **60%**
  - Phase C: `compute/__init__.py` ≥ **65%** (already met with both trees;
    keep ≥65% and cover prep helpers)
  - Package: `referia.assess` ≥ **65%** (excluding intentional `review_new`
    deferral where needed)
  - No regression below current % on already-strong modules

### Non-goals

- Full branch coverage of every LLM vendor branch.
- Integration / live OpenAI tests in CI.
- Rewriting Assess APIs (that belongs in CIP-0012 / other design CIPs).
- Deep tests for `review_new.py` while it remains a candidate for removal.

## Implementation Plan

1. Accept this CIP → create backlog tasks (one per phase below).
2. **Phase A — `data.py`:** column helpers, element get/set, `set_index`
   pre/post, `automapping`, dialect strict_columns with synthetic frames.
3. **Phase B — `review.py`:** `template_to_value`, `create_document`,
   `value_updated`, `load_flows`, visibility helpers with mocks.
4. **Phase C — `compute` registry:** `prep_all` / `preprocess` stubs;
   registry smoke for `_compute_functions_list` / `_llm_functions_list`.
5. **Phase D — `review_new.py`:** triage → defer deep coverage; document
   fold/delete as follow-on.
6. Re-run package report; update this CIP with final numbers; close.

## Backward Compatibility

Tests only (plus a small `drop_column` KeyError message typo fix in
`data.py`). No intentional runtime API change.

## Testing Strategy

- New files under `tests/`: `test_assess_data_coverage.py`,
  `test_assess_review_coverage.py`, `test_assess_compute_coverage.py`.
- `pytest` `testpaths` includes `tests` and `referia/tests`.
- Avoid constructing full `Reviewer` / `WidgetCluster` / Compute-with-
  entries in unit tests (known hang); bind unbound methods onto
  `MagicMock` instead.
