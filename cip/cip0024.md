## Summary

Several dialogue Address stages document Access of upstream products
(`grounds.yml`, `turns.yml`, `phrases.yml`, …) in Liquid prose, but
their frontmatter only declares `records.parquet` or `constants.yml`.
Referia compute then opens the sibling files via
`_load_info_yaml_rows` / direct `Path` reads under `_config_info_dir()`.

That bypasses lynguine’s registered data flow. Soft graph edges appear
in CIP-0023 Option B discovery only because the reads are invisible to
the interface. This CIP inventories every such bypass and promotes each
to a **declared store** on the consuming stage, then teaches compute to
load through that registration (not a free filesystem guess).

Enables honest Option B pipeline discovery (CIP-0023 Phase 2) and
keeps `named_store_status` (CIP-0017 / REQ-0011) aligned with what
Address actually reads.

## Motivation

Lynguine is built so data flow is explicit on the interface. The formats
study already has a gold-standard example: `05_distance` joins grain as
`data: scores.yml` rather than opening the file in compute.

`07_part_b` (and several siblings) instead say in comments “wrapper
reads `grounds.yml`” while frontmatter `input` is only the packed
corpus row. Option B store-join therefore missed `07_grounds →
07_part_b` even though the page’s Access section depends on it.

Leaving those as soft deps trains authors to document flow in prose
and implement it off-book. Prefer the opposite: if Address needs a
product, register it; if registration is awkward (grain mismatch),
fix the registration model — do not Path-open quietly.

| Stage | Key | Product |

Discovery must treat **any** store-shaped top-level key with
`filename` (+ optional `directory`) as a node I/O slot — not only
`input` / `output` / `cache` / `data`.

### Design: two registration classes

**Class A — index-aligned joins** (already works)

When the sidecar shares the review index with `input` (formats study:
corpus `Name`), declare it as `data:` exactly like `05_distance` →
`scores.yml`. Lynguine joins it into the frame; compute reads columns
from the current row / joined series; `named_store_status` sees it.

**Class B — grain-mismatched sidecars** (the soft-dep bulk)

`grounds.yml`, `phrases.yml`, `chunks.yml`, `turns.yml` are
**tall** (phrase / unit / turn grain). Consumer pages often sit on a
**singleton** corpus row (`Name: corpus`). Outer-joining them as
`data:` onto that index is wrong (explodes or fails the join).

For Class B, declare an explicit **sidecar store** on the interface
that:

1. Appears in frontmatter as a **product-named** store key that is
   *not* in lynguine `valid_data_types` (so `from_flow` does not join
   it onto the review index). Canonical keys for this study:

   | Key | Product | Notes |
   |-----|---------|-------|
   | `grounds` | `grounds.yml` | phrase grain |
   | `phrases` | `phrases.yml` | phrase grain |
   | `turns` | `turns.yml` | turn grain |
   | `chunks` | `chunks.yml` | unit grain |
   | `codebook` | `codebook.parquet` | VQ row |
   | `roster` | `documents.yml` | hand seed; **not** `documents:` (reserved for generate-document) |
   | `grain` | `scores.yml` | Class B only; Class A keeps ``data: scores.yml`` |
   | `pack` | `records.parquet` | write on `02_embed` (existing) |

   Spike (2026-11-04): Interface retains `grounds:`; `from_flow`
   partitions stay `input`/`output` only — no lynguine fork required.
2. Is visible to `named_store_status` (already walks any
   store-shaped interface item).
3. Is **not** auto-joined into the primary CustomDataFrame index.
4. Is loaded by compute **only** through the declared store path.
   Undeclared sibling Path opens under `_config_info_dir` are
   **refused** (`ValueError`). Missing declared files still return
   `[]` (empty product).

Do not use referia dialect `scores:` as a sidecar key (remapped to
`output`). Name-aligned grain stays on `data:` (Class A).

### What stays orphan by nature

| Store | Role |
|-------|------|
| `_data/corpus/documents.yml` | Hand roster / seed into `01_chunk` (often gitignored) |
| `_data/corpus/constants.yml` | Study seed; read as `constants:` / `input:` |

These need no upstream stage writer. Discovery should label them
**external seeds**, not soft deps.

### Compute contract after this CIP

1. Inventory above has a declared store on each consumer page.
2. Wrappers accept optional in-memory args (unchanged for tests) but
   when args are missing they load via
   `load_declared_store(interface, role)` (name TBD), not
   `_load_info_yaml_rows("fixed.yml")`.
3. `_load_info_yaml_rows` either becomes a thin deprecated adapter
   over declared stores or is removed once callers are migrated.
4. CIP-0023 Option B discovery: writer(`output`|`pack`) →
   reader(`input`|`data`|sidecar|`constants`) by path equality;
   Class B sidecars produce real edges (e.g. `07_grounds` →
   `07_part_b` via `grounds.yml`).

### Out of scope

- CIP-0023 Phase 2 refit/LLM multiverse execution
- Auto-inferring edges from Liquid prose
- Migrating private corpus content
- Changing estimator maths on Part A/B / sequence / multiverse

## Implementation Plan

1. **Lock the Class B keying**
   - Spike: can formats pages declare `grounds:` / `phrases:` etc.
     without lynguine rejecting the interface?
   - If not, open a minimal lynguine CIP for non-join registered
     stores; referia waits on that for Class B only.
2. **Study frontmatter (dods-ai-dialogue)**
   - Add declared stores for every inventory row on the consumer
     pages; keep `05_distance` / `06_compare` Class A pattern for
     Name-aligned joins.
   - Extend `named_store_status` Liquid on those pages so sidecars
     show in Store status.
3. **Referia compute**
   - Introduce load-via-declaration helper; migrate wrappers in the
     inventory table; add unit tests that fail if a wrapper opens a
     corpus product path not present on the interface.
4. **Discovery hook (CIP-0023 follow-on)**
   - `discover_pipeline_edges(root)` over permalink markdown using
     frontmatter + all store-shaped keys (including `pack` and Class
     B); golden-compare against Option A `pipeline.yml` edges for the
     formats study (document intentional diffs).

## Backward Compatibility

- Study YAML and compute land together: a consumer stage without the
  sidecar declaration fails closed when Address tries to load that
  product.
- Existing PopulateButton row_args / tests that pass in-memory
  frames unchanged.
- `pipeline.yml` Option A remains authoritative until discovery is
  validated; this CIP does not delete it.

## Testing Strategy

- Unit: each migrated wrapper loads from a fake interface store spec;
  absent declaration → clear error (no silent empty list) once
  fallback is removed.
- Study smoke: `07_part_b`, `10_sequence`, `11_multiverse`, sidings
  still produce outputs when declared stores exist.
- Discovery: formats-study inferred edges include
  `07_grounds → 07_part_b`, `01_turns → 10_sequence`,
  `02_embed → 03_vq` (via `pack`), and do not treat
  `constants.yml` as a missing writer.
