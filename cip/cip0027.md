# CIP-0027: Migrate developer packaging from Poetry to uv

> CIPs describe HOW to achieve requirements (WHAT).  
> Parallel to [lynguine CIP-001B](https://github.com/lawrennd/lynguine/blob/main/cip/cip001B.md) (implemented). Softly supports [REQ-000A](../requirements/req000A_secure-llm-dependencies.md) by keeping optional LLM extras on a standard, lockable install path.

## Summary

Replace Poetry as referia’s developer packaging tool with **uv**: PEP 621 `pyproject.toml`, `uv.lock`, and CI/docs that use `uv sync` / `uv run` / `uv build` instead of `poetry install` / `poetry run` / `poetry build`.

PyPI consumers who `pip install referia` (or `pip install 'referia[llm]'`) are unaffected. Optional extras (`llm`, `distance`), the `referia` console script, git/URL/platform deps, and docs/dev dependency groups remain.

## Motivation

Referia still uses a Poetry-native surface while its infrastructure sibling **lynguine** has already moved to uv (CIP-001B):

- `[tool.poetry]` metadata (not PEP 621)
- `poetry.lock` + `poetry-core` build backend
- Three GitHub workflows install Poetry then wrap steps in `poetry run` / `poetry build` / `poetry publish`
- Sphinx `docs/conf.py` reads `pyproject['tool']['poetry']` for name/version/author
- Contributor and example docs (including CIP-0026’s `poetry run referia serve` path) prescribe Poetry
- Cursor rule `.cursor/rules/general.mdc` mandates Poetry for builds

Migrating keeps the monorepo-adjacent tooling story consistent, speeds CI installs, and aligns with PEP 621. This is a **tooling** change, not a review API or `_referia.yml` change.

## Detailed Description

### Current state

| Piece | Today |
|-------|--------|
| Metadata | `[tool.poetry]` + `[tool.poetry.dependencies]` |
| Extras | `[tool.poetry.extras]` → `llm`, `distance` |
| Groups | `[tool.poetry.group.docs]`, `[tool.poetry.group.llm]` (mirrors extra), `[tool.poetry.dev-dependencies]` |
| Scripts | `[tool.poetry.scripts]` → `referia` |
| Build | `poetry-core` / `poetry.core.masonry.api` |
| Lock | `poetry.lock` |
| Hard deps | Git `lynguine` (+ extras); URL `en_core_web_sm`; Darwin-only `gspread_pandas` / `appscript` |
| CI | `python-tests.yml` (macos), `docs.yml`, `publish.yml` all Poetry |
| Docs metadata | `docs/conf.py` → `tool.poetry` |
| Agent rule | `.cursor/rules/general.mdc` → “Always use poetry for builds” |

### Target state

| Piece | After |
|-------|--------|
| Metadata | PEP 621 `[project]` (+ `[project.optional-dependencies]`) |
| Dev/docs deps | `[dependency-groups]` (`dev`, `docs`) — uv’s native groups |
| Scripts | `[project.scripts]` → `referia` |
| Build | `hatchling` (same choice as lynguine CIP-001B) |
| Lock | `uv.lock` (commit); remove `poetry.lock` |
| Hard deps | PEP 621 / PEP 508: git source, URL source, `sys_platform == 'darwin'` markers |
| CI | `astral-sh/setup-uv` + `uv sync --extra …` / `uv run` / `uv build` |
| Docs metadata | Read `[project]` (name, version, authors) |
| Agent rule | Prefer uv for builds / sync / run |

### Design decisions

1. **Full migration, not dual tooling.** Drop Poetry as the supported contributor path. Do not keep `poetry.lock` alongside `uv.lock` long-term.

2. **Preserve install surface for library users.**
   - `pip install referia`
   - `pip install 'referia[llm]'` / `'referia[distance]'`
   - Editable: `pip install -e ".[llm]"` still works; contributors prefer `uv sync --extra llm --group dev`

3. **Collapse LLM dual path.** Today both `[tool.poetry.extras].llm` and `[tool.poetry.group.llm]` exist so `--extras llm` and `--with llm` work. After migration: one `[project.optional-dependencies].llm` only. Document `uv sync --extra llm` (and `pip install 'referia[llm]'`); do not reintroduce a Poetry-style group named `llm`.

4. **Map Poetry groups/extras explicitly.**
   - Poetry extras → `[project.optional-dependencies]` (`llm`, `distance`)
   - Poetry docs / pytest-style deps → `[dependency-groups]` (`docs`, `dev`)
   - Drop empty/unused `[tool.poetry.group.dev.dependencies]` and the stray `[build]` script stub

5. **Express referia-specific dependency shapes in PEP 621.**
   - **Git:** `lynguine` from `https://github.com/lawrennd/lynguine.git` (`main`) with extras `documents`, `parquet` — use uv/PEP 508 git dependency form; smoke `uv lock` early
   - **URL:** `en_core_web_sm` wheel/sdist URL (spaCy model) — keep as a direct URL dependency
   - **Platform:** `gspread-pandas` and `appscript` with `sys_platform == 'darwin'` markers (CI tests already run on `macos-latest`)

6. **Version and publish.** Keep release-tag ↔ package-version check. Prefer `uv build` + Trusted Publishing / token publish; replace `poetry version -s` with reading `[project].version` (or `uv version` once chosen at implementation). Mirror lynguine’s post-001B publish workflow shape where practical.

7. **Example / docs wording.** CIP-0026 standardised `poetry run referia serve`. Update those strings to `uv run referia serve` (or plain `referia serve` after `uv sync`) in README, `examples/**`, and Sphinx/LLM docs — without reopening CIP-0026’s example *content*.

8. **VibeSafe `.venv-vibesafe`.** Unrelated; leave the whats-next venv alone.

9. **Sibling lynguine.** Prefer depending on lynguine’s uv-era `pyproject` (already on `main`). No fork of lynguine packaging inside this CIP.

### Alternatives considered

| Approach | Why not (for this CIP) |
|----------|-------------------------|
| Keep Poetry; only add uv for CI cache speed | Two lock/tool stories; diverges from lynguine |
| Stay on Poetry until lynguine is on PyPI only | Still leaves contributor/CI Poetry; git dep already works under uv |
| Dual `poetry.lock` + `uv.lock` for a transition | Drift risk; CIP-001B rejected this for lynguine |

### Risks

- **Lock success** for git lynguine + spaCy URL + Darwin markers is the main unknown — run `uv lock` before rewriting all workflows.
- Publish workflow is highest blast radius; dry-run `uv build` + twine/uv check before a release.
- `docs/conf.py` breaks if metadata moves without updating the Sphinx reader (authors become a list of tables under PEP 621).
- Wildcard Poetry deps (`"*"`) should become explicit loose ranges where lynguine already tightened constraints; lockfile still pins installs.
- Docs workflow pins Poetry `1.5.1` today — remove that pin entirely rather than upgrading Poetry.

## Implementation Plan

1. **Convert `pyproject.toml`**
   - Move package metadata to `[project]`
   - Move runtime deps (including git, URL, platform markers)
   - Move `llm` / `distance` to `[project.optional-dependencies]`
   - Move `dev` / `docs` to `[dependency-groups]`
   - Move `referia` to `[project.scripts]`
   - Set hatchling build backend and package includes
   - Remove Poetry tables and the unused `[build]` stub

2. **Lock and local verify**
   - `uv lock` → commit `uv.lock`
   - Remove `poetry.lock`
   - `uv sync --extra llm --group dev` (and a non-LLM sync path)
   - `uv run pytest`, `uv run referia --help`

3. **CI workflows**
   - `python-tests.yml`: setup-uv; sync; `uv run pytest` (keep macos unless Linux is proven for Darwin-only deps)
   - `docs.yml`: sync with docs group; `uv run` sphinx / test_build; drop `snok/install-poetry`
   - `publish.yml`: sync; version check from `[project].version`; `uv build`; publish; drop Poetry

4. **Docs, examples, and agent rule**
   - Update `docs/conf.py` for `[project]`
   - Update README / `docs/installation.rst` / `docs/contributing.rst` / LLM docs
   - Sweep `examples/**` and CIP-0026-era `poetry run referia serve` strings to `uv run referia serve`
   - Change `.cursor/rules/general.mdc` to uv (or “use uv for builds”)

5. **Smoke publish path**
   - Local `uv build` + artifact check
   - Clean env: install wheel; import `referia`; confirm `referia` console script; optional `llm` imports when installed with extra

## Backward Compatibility

- **Library API / review configs:** unchanged.
- **PyPI installers:** unchanged (`pip install referia` and extras).
- **Contributors:** must use uv (or plain pip against the PEP 621 project) instead of Poetry.
- **Application repos** under OneDrive that `pip install` / editable-install referia: unaffected if they already use pip; Poetry-based checkouts of *this* package need `uv sync`.

## Testing Strategy

- CI green after workflow swap (`python-tests`, docs build)
- Local: `uv run pytest` with and without `--extra llm` as appropriate
- Package: `uv build`; install wheel in a clean env; `import referia`; `referia --help`
- Confirm spaCy model import path still resolves after URL dep conversion
- Confirm Darwin-marked deps install on macos CI
- Publish job: version-tag check still fails closed on mismatch
