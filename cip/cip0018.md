# CIP-0018: Stacked inherit view — ancestor sections above child on one page

> **Note**: CIPs describe HOW to achieve requirements (WHAT).

## Summary

Keep today's child view as the **default**. Offer an allowlisted set of **browser query parameters** so a reviewer can switch that page to a stacked inherit view (ancestor `viewer:` / `review:` **above** the child's) without changing `_referia.yml`.

Addresses [REQ-0012](../requirements/req0012_same-page-inherited-sections.md). Display-only: query values cannot change paths, inherit directories, or writability ([REQ-000B](../requirements/req000B_secure-web-and-ci-surface.md), [CIP-000E](./cip000E.md)).

## Motivation

Referia configs routinely inherit. Real chains include:

```
people/progress → people/relationship → people/achievements → people/letters
theses/examined/pdfpages → theses/examined/introduction
```

lynguine already merges `input`, `mapping`, and (when listed) `viewer` so the child's **data** can see parent fields. Referia's `_process_parent` then:

1. **Ignores** parent `review` and `compute` by default, so the child's scoring form is only the child's widgets.
2. **Appends** `viewer`.
3. Injects a static *Parent assesser available here* link at the top of the viewer.

The reviewer who is writing a letter therefore sees a pointer to achievements, not the achievement and relationship sections themselves. CIP-000C makes that pointer a real URL, but it is still a **different view**. The parent-link backlog ([2026-07-16_parent-assessor-link-index](../backlog/features/2026-07-16_parent-assessor-link-index.md)) only makes the hop land on the right index; it does not put the sections on one page.

Authors already work around this by copying parent Liquid into the child viewer (`people/achievements` restates relationship fields; `people/letters` loops `achievementComment`). That duplicates structure and drifts.

The missing composition is: **one page, ancestor sections above, child sections below**, with each block still labelled as the config it came from.

The everyday view should stay as it is. Switching to the stacked page is a **request option** (bookmarkable URL), not a config rewrite.

## Detailed Description

### What this is not

| Nearby work | Difference |
|-------------|------------|
| CIP-0010 `display.layout: inline_list` | Many **rows** on one page. This CIP stacks **inherit layers** for one row. Orthogonal: stacked inherit can sit inside `side_by_side` or `inline_list`. |
| `inherit.append: [review]` via lynguine `__getitem__` | Flattens parent+child lists (`par_val + val`) and **drops provenance**. Parent widgets mix with the child's. Default ignore of `review` exists so that does not happen by accident. |
| CIP-000C parent URL | Navigation remains; stacked compose means you do not need it to *read* ancestor sections. |
| Bug [web-inherit-not-applied](../backlog/bugs/2026-07-14_web-inherit-not-applied.md) | That bug is "does WebReviewer resolve inherit at all?". This CIP assumes Interface already loads the parent chain (Jupyter path) and **presents** each layer. Confirm/fix the bug as a prerequisite, not as this design. |

### Default view

Omitted options equal today's behaviour: ignore parent `review`/`compute`, append `viewer`, inject the parent-assessor link. No `_referia.yml` change is required to keep using a child as it is.

### Browser options (primary switch)

Query parameters are already how this server selects a record (`?index=`) and filters listings (`after`, `before`, `current`). Add a small **allowlist** of view options on the same review URL. Example:

```
/people/letters/?index=Alice&compose=stacked
/people/letters/?index=Alice&compose=stacked&inherit_review=0
```

v1 allowlist (case-insensitive; other keys ignored):

| Param | Values | Default | Effect |
|-------|--------|---------|--------|
| `compose` | `link`, `stacked` | `link` | Inherit presentation |
| `inherit_viewer` | `0`, `1` | `1` when stacked, ignored otherwise | Include ancestor `viewer:` blocks |
| `inherit_review` | `0`, `1` | `1` when stacked, ignored otherwise | Include ancestor `review:` blocks |

`compose=stacked` walks the Interface parent chain and renders each layer's **own** `_data["viewer"]` and `_data["review"]` (not the merged `__getitem__` view), oldest ancestor first, then the child.

Page chrome should expose these as ordinary links or a compact control (for example “Show inherited”) that sets or clears the query string, so reviewers need not type the names. HTMX index/field fetches must **preserve** the allowlisted params the same way trailing-slash redirects already preserve `?index=`.

Optional YAML `inherit.compose: stacked` may still exist as an **author default** for a config that should always stack. The query string overrides it for that request (`compose=link` forces the default view). Most configs omit it.

Keep lynguine merge for data (`input` hstack, constants, mapping append). Do not fork lynguine to learn about stacking. Referia owns presentation, matching *handle implicit behaviour explicitly in the application layer* and *extend infrastructure, don't fork it*.

Do **not** introduce a third `display.layout`. Stacking inherited content is inherit composition, not chrome. A `layout=` query override of `side_by_side` / `inline_list` would also be display-only and allowlist-safe, but it belongs with CIP-0010, not this CIP.

### Why query parameters are safe here

Untrusted request input (CIP-000E): treat every query value as hostile. These options are safe **because they only select among named presentations already implemented in referia**. They must not load files, change jails, or widen writes.

**Allow**

- Enum values from the table above
- Invalid or unknown values → ignore, log server-side, fall back to the next precedence (query → YAML author default → `link`). Do not 500 and do not echo the raw value into HTML

**Forbid (ignore even if present)**

- `writable`, directories, filenames, paths
- Widget types, Liquid, field names, compute
- Anything that would alter `Interface` loading or which stores `Save` touches

`inherit.writable` stays a **config** fact. `compose=stacked` never makes ancestor review editable. Read-only ancestor widgets remain read-only.

Boolean params accept only `0`/`1` (and `true`/`false` if we want a second spelling). Any other string is invalid → default.

Jupyter has no query string. It follows YAML author default or `link`. Stacked-from-the-browser is a web feature.

### Layer walk

`Interface` already holds `_parent`. Add a referia helper (name bikeshed: `interface_layers()`) that returns root-first:

```
[(title, directory, viewer_entries, review_entries), ...]  # last item is self
```

Each tuple reads that node's `_data`, not `interface["viewer"]` (which would already be appended). Circular inherit remains lynguine's existing error.

`WebReviewer.get_viewer_specs` / `get_review_specs` (and Jupyter widget creation) concatenate:

1. For each ancestor layer: wrap that layer's entries in `type: Section` with `title` = that config's `title` (fallback: directory name). Mark the section `inherited: true` and `writable` from that hop's `inherit.writable`.
2. Then the child's unwrapped (or optionally section-titled) local entries.

Side-by-side chrome is unchanged: viewer pane stacks ancestor viewers above the child viewer; review pane stacks ancestor review sections above the child form.

### Writable vs display

Default `inherit.writable: false` stays. Under `compose: stacked`:

- Ancestor **viewer** is always display.
- Ancestor **review** widgets render with existing values from the child's already-hstacked data.
- Those widgets are **read-only** unless that hop set `writable: true` **and** the field is in a store the child session may write. Do not quietly persist parent scores into the child's output file.
- `writable: true` is the advanced case (parent output really is this session's writable store). Document it; tests must cover the false default.

### Parent-assessor link

When `compose: stacked`, do **not** inject the static *Parent assesser available here* HTML into `viewer`. Put a small "open in parent" control on each inherited Section header, with `?index=` for the current record (this subsumes the 2026-07-16 backlog for stacked mode). `compose: link` keeps the existing blob; that backlog still applies there.

### Example: letters

Leave `people/letters/_referia.yml` as it is. Open:

```
/people/letters/?index=Alice
```

for today's letter view, or:

```
/people/letters/?index=Alice&compose=stacked
```

for ancestor sections above the letter widgets (progress / relationship / achievements, whatever the chain actually is), each labelled. `inherit_review=0` keeps ancestor viewers only.

The author can later delete copied relationship Liquid from child viewers once stacking is trusted; that cleanup is application-repo work, not this CIP.

### Jupyter

No browser query string. Jupyter uses YAML `inherit.compose` if present, otherwise `link`. Do not invent a parallel `viewer_inherit` flag. Web is the surface that honours the allowlisted params (REQ-0008).

## Implementation Plan

1. **Prerequisite**: Confirm `WebReviewer` constructs `referia.config.interface.Interface` (parent chain loaded). If it raw-loads YAML, fix [2026-07-14_web-inherit-not-applied](../backlog/bugs/2026-07-14_web-inherit-not-applied.md) first.
2. **`interface_layers()`** on referia `Interface`: root-first `(title, directory, viewer, review)` from `_data` per node.
3. **Parse view options**: allowlisted query params on review routes; optional YAML `inherit.compose` as author default; precedence query → YAML → `link`. Unknown query values ignored (log, default).
4. **Preserve params** on HTMX panel fetches and trailing-slash redirects. Page control that sets `compose=stacked` / clears it.
5. **`WebReviewer` spec assembly**: when stacked, wrap ancestor entries as `Section` with `inherited` / `writable` metadata; skip the injected parent-link viewer element. Honour `inherit_viewer` / `inherit_review`.
6. **Render**: inherited Sections use existing collapsible `<details>` (CIP-0014 persist keys still work). Read-only widgets for `writable: false`. Header link includes `?index=` plus current view params.
7. **Jupyter**: YAML / `link` only.
8. **Do not change** lynguine default ignore/append. Stacked compose does not require putting `review` on `append`.

## Backward Compatibility

- No query string and no YAML `compose` equals today's view. Existing configs unchanged.
- `inherit.append` / `ignore` keep today's data-merge meaning.
- Bookmarks and listing links without the new params behave as they do now.
- Adding `?compose=stacked` is opt-in per request; authors are not required to edit `_referia.yml`.

## Testing Strategy

Fixture chain of three `_referia.yml` files (grandparent viewer+review, parent viewer+review, child viewer+review), shared index, parent fields present on the child frame via inherit input.

- No params / `compose=link`: child specs only for review; parent link present; no inherited Section titles.
- `compose=stacked`: ancestor sections appear above child in both viewer and review; titles match ancestor `title` fields; order is grandparent, parent, child.
- `compose=stacked&inherit_review=0`: ancestor viewers only; child review unchanged.
- `compose=stacked&writable=true` (or any path-like extra): ignored; ancestor review stays read-only; no extra files loaded.
- `compose=not-a-mode`: treated as default `link`, not an error page.
- Query params survive index change (HTMX) so the stacked view does not snap back.
- `writable: false` in YAML: ancestor review controls are not persisted to the child output store even when stacked.
- CIP-0010 `inline_list` still lists rows; stacked inherit does not flatten the working set.
