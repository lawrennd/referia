## Summary

Let a `viewer:` Markdown (or HTML) entry wrap selected headings in closed
`<details>` so long LLM replies stay collapsed while student prompts stay
visible. Opt-in from `_referia.yml`; unchanged by default.

Addresses the CIP-000B follow-on that left collapsing headings *inside* a
viewer markdown blob out of the first review-section work.

## Motivation

Worksheet marking joins a Socratic dialogue as one markdown blob. Each
exchange is `### User` then `### LLM`. The LLM replies dominate the left
pane, which makes it hard to scan what the student actually asked while
marking the handwritten reflection.

A general subsection parser (turning exchanges into nested records) would
be more than this workflow needs. The files already have a heading
contract. Display can collapse by heading text after `markdown2html`.

## Detailed Description

After Liquid evaluation and `markdown2html`, `render_viewer` walks HTML
`h1`–`h6` tags. When a heading’s text matches a configured name
(case-insensitive; first word also matches, so `LLM` catches `LLM reply`),
the heading becomes a `<summary>` and the following siblings until the
next heading go inside `<details class="viewer-heading-collapse">`.

Config (on a viewer entry):

```yaml
viewer:
  - liquid: "{{content}}"
    collapse:
      headings: [LLM]
      default: closed
```

- `headings`: list of heading texts to wrap. Empty / omitted → no wrap.
- `default`: `closed` (default) or `open`.

Unmatched headings (`### User`, `## Exchange 1`) stay in the open flow.

Reuse the existing sessionStorage persist pattern (`data-section-key`) so
opened LLM blocks survive HTMX record swaps, same as PDF entries and
review `Section` widgets.

This is display-only. It does not parse markdown into fields, change
Access loaders, or invent a subsection-parser dialect.

**Not this CIP:** splitting dialogues into per-turn records, collapsing
review-form widgets (already `type: Section`), or Jupyter widget chrome.

## Implementation Plan

1. Parse `collapse:` on the viewer spec in `referia/web/render.py`.
2. Post-process Markdown / HTMLMath / HTML viewer HTML to wrap matching
   headings.
3. Style `.viewer-heading-collapse` and persist open state in `base.html`.
4. Unit tests in `tests/test_web_render.py`.

## Backward Compatibility

No change unless `collapse.headings` is set. Existing viewers keep a
single unwrapped markdown blob.

## Testing Strategy

- Matching `### LLM` wraps; `### User` does not.
- Absent `collapse:` leaves headings unwrapped.
- `default: open` emits the `open` attribute.
- Body until the next heading is inside `<details>`.
- Case-insensitive / first-word match.
