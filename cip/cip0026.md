## Summary

Make the package `examples/` tree (and Sphinx example entry points) the reproducible way to learn referia: every runnable demo documents **`poetry run referia serve --directory …`** (or `--root` where multi-config is the point), retires `referia-web` / `python -m referia.web.app` as the advertised launch path, and adds a small **numeric scoring** example that exercises YAML `add` / `multiply` / `gte` (and related) compute once those primitives land.

This CIP is documentation and fixture work, not a new runtime feature. Numeric primitives themselves remain the feature backlog `2026-11-07_yaml-numeric-compute-primitives` (implementation may land on a sibling branch and merge first).

## Motivation

Package examples have drifted from the product surface:

1. **Launch commands disagree.** `examples/overview_inline_list/README.md` still leads with `referia-web` and `python -m referia.web.app`. `topic_scatter_click` mentions `referia serve` but keeps `referia-web` as an alternate. `subject_grain_uq` is already on `referia serve`. Sphinx `docs/usage/catalog_schedule.rst` already shows the correct CLI — READMEs should match.
2. **Sphinx toctree is broken.** `docs/index.rst` includes `examples/index`, but `docs/examples/index.rst` is missing. Checkpoints under `docs/examples/.ipynb_checkpoints/` and aged notebooks (`test_referia.ipynb`, `test_compute.ipynb`) are not a coherent onboarding path for the web reviewer.
3. **LLM / thesis snippets are script-centric.** `examples/llm_*.py|yml` and `thesis_llm_review_example.*` still teach programmatic or notebook-era usage without a clear “open this directory under `referia serve`” path, so newcomers miss the primary UI.
4. **Numeric compute has no demo.** Unit tests and (planned) `docs/usage/compute.rst` snippets are not enough for reviewers who learn by running a directory. A miniature scoring example closes that gap once primitives exist.

Without a single CIP, this work tends to land as one-off README edits and never repairs the Sphinx/LLM surface.

### Canonical README “Run” block

Every serveable example README should use approximately:

```bash
poetry install   # once, from referia package root
poetry run referia serve --directory examples/<name>
# Open the printed URL (default http://127.0.0.1:8000)
```

Extras (bake scripts, `--synthetic`, LLM extras) stay after the canonical block.

### Numeric scoring sketch (Phase B)

Minimal shape (exact field names free to adjust on implement):

```
numeric_scoring/
├── README.md
├── _referia.yml      # input YAML + compute ops + review PopulateButton(s)
└── info/
    ├── records.yml   # candidates with raw criterion scores / weights
    └── scores.yml    # derived totals / pass flags (mutable or compute-filled)
```

YAML compute should call registered referia functions (`multiply`, `add`, `gte`, …) rather than embedding Python in the example. Document that these are **referia assessment helpers** pending vongole, consistent with the numeric docs backlog.

## Backward Compatibility

- No API breaks. Example README and docs changes only (plus optional new example directory).
- Retiring notebooks may remove a path some maintainers still open; Phase C should leave a one-line pointer in the examples index if anything useful remains.
- `referia-web` entry points, if still installed, need not be deleted in this CIP — only demoted out of documentation. A separate backlog may remove the console script later.

## Testing Strategy

- Manual: each serveable example starts with `poetry run referia serve --directory …` and loads without traceback.
- Numeric example: PopulateButton (or equivalent) produces expected derived columns; Save round-trips.
- Sphinx: `docs/examples/index` builds (no missing toctree target).
- Optional: lightweight smoke test that example `_referia.yml` files parse / `Interface.from_file` succeeds (no full browser automation required for this CIP).
