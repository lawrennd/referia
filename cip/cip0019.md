# CIP-0019: Grain methods — sklearn partitions vs soft MPPCA

## Summary

Subject grain today is one algorithm (soft mixture of PPCA) that also owns the catalogue, the Assess loop, and the figures. sklearn `KMeans` is already a hidden initialiser inside that mixture. This CIP splits **catalogue state** from **grain methods**, adds two sklearn partition methods (k-means and agglomerative) as first-class alternatives, and keeps MPPCA as the method that uniquely owns soft responsibilities, local \(U_q\) planes, and Propose / Confirm / Undo.

Addresses [REQ-0010](../requirements/req0010_dialogue-pipeline-in-referia.md) (interactive subject grain from config; knobs as parameters). Complements [CIP-0012](./cip0012.md) (model vs figures vs naming) without replacing MPPCA.

## Motivation

The packed corpus is a matrix of L2-normalised phrase embeddings. Several legitimate analyses start from that matrix:

- **Hard partitions** (k-means, hierarchical): choose \(k\), assign each phrase to one cluster, inspect, name, then run document EMD on one-hot \(R\).
- **Soft MPPCA**: start at \(k=1\), split mass on a local Bishop–Tipping plane, keep soft \(R\).

Those are different algorithms with different controls and different pictures. They share a **catalogue**: a row-stochastic \(R\) (\(n \times k\)), topic keys, labels, and a focus. Naming and document distance already consume that catalogue; they should not import `mppca_fit`.

Today `referia/assess/compute/mppca.py` (~1.8k lines) mixes:

| Concern | What lives in `mppca.py` today |
|---|---|
| PPCA / EM | `fit_weighted_ppca`, `mppca_fit`, `propose_split`, SVD helpers |
| sklearn clustering | `KMeans` used only to initialise MPPCA when \(k \ge 2\) |
| Catalogue | `topic_keys`, `format_topic_tree_markdown`, parent maps, seed / propose / confirm / undo façades |
| Figures | `rebuild_uq_by_topic` imports Plotly builders |

`subject_grain_seed_fit` always calls `mppca_fit`. The 03_grain UI exposes σ² and EM as if they were *the* grain knobs. Adding k-means by stuffing another `if method == "kmeans"` into `mppca.py` would freeze the wrong structure.

sklearn is already a dependency (`scikit-learn >= 1.3`). Hierarchical clustering (`AgglomerativeClustering`) is the second partition method that forces the registry pattern: if two sklearn estimators and one mixture model all write the same catalogue, the split is real.

## Detailed Description

### Survey (2026-10-22)

**Shared contract already exists, unnamed.** `document_soft_topic_distributions` (CIP-0016) sums phrase rows of \(R\) per document. It does not care whether those rows are soft posteriors or one-hot. `subject_grain_prepare_label` ranks phrases by a column of \(R\). `responsibilities_to_labels` is MAP. Hard clustering is already representable: one-hot \(R\).

**MPPCA-only geometry.** `component_local_plane`, `local_uq_plotly_spec`, `proposed_split_plotly_spec`, and Propose / Confirm / Undo have no meaning for a Voronoi partition or a dendrogram cut. CIP-0012 explicitly listed “do not replace soft \(R\) with hard labels as primary state” as a *non-goal for MPPCA*. That still holds for the MPPCA method. It does not forbid other methods whose primary state *is* a hard partition encoded as one-hot \(R\).

**Hidden k-means.** `mppca_fit` for \(k \ge 2\) runs sklearn `KMeans(n_clusters=k, init="k-means++", n_init=…)` then EM. Users cannot stop after the k-means step, cannot set `init` / `n_init` from 03_grain, and cannot compare that partition to the mixture.

**Seed workflow is MPPCA-shaped.** CIP-0015 seed is \(k=1\) then split. K-means and agglomerative are “choose \(k\), fit once”. Reset-to-\(k=1\) is an MPPCA Assess action, not a generic clustering action.

**Figures are stored as catalogue.** `uq_by_topic` / `uq_spec` are Plotly JSON keyed by topic. CIP-0012 still wants plane parameters as the stored artefact and figures rebuilt on view. This CIP does not finish that; it does require that **the figure builder is method-specific** so k-means does not pretend to have a local \(U_q\).

**Knobs belong on the parameters store.** 03_grain now keeps σ², EM, `label_prompt`, `label_model`, and `n_exemplars` in `parameters.yml`, not cache or scores. New method knobs follow that rule.

**Embeddings are L2-normalised** (CIP-0015 embed). Euclidean k-means on that sphere is spherical k-means (cosine). Ward linkage requires Euclidean; `average` / `complete` / `single` may use `metric="cosine"`.

### Target layers

```
parameters.yml          cluster_method + method knobs (writable)
        │
        ▼
grain catalogue         R, topic_keys, labels, parent, tree, focus
        │
        ├── mppca                 soft R, component_fits, Propose/Undo, U_q figures
        ├── kmeans                hard R, sklearn KMeans, global PCA scatter
        └── agglomerative         hard R, sklearn AgglomerativeClustering,
                                  global PCA + optional dendrogram
        │
        ▼
naming / EMD            read R (and embeddings / doc_ids); method-agnostic
```

Do **not** put k-means or agglomerative inside `mppca.py`. Do **not** teach 04_distance about methods.

### Catalogue (shared)

A grain fit writes, and only writes, these Assess fields (output / scores):

| Field | Meaning |
|---|---|
| `responsibilities` | \(n \times k\), rows sum to 1 (soft or one-hot) |
| `topic_keys` | `["T0", …]` |
| `topic_labels` | key → title (provisional `Topic i` until named) |
| `topic_parent` | genealogy; hard methods may be flat (`None`) or, for agglomerative, optional cut-tree parents |
| `topic_tree` | Markdown derived from keys / labels / parent / \(R\) |
| `focus_topic` | which topic the viewer is looking at |
| `cluster_method` | **not** here — parameters store |
| figures | method-specific map + current spec; see below |

Helpers that are not MPPCA (`topic_keys`, one-hot from labels, tree Markdown, parent maps) move to a small `grain` catalogue module. `mppca.py` imports them.

### Method protocol

Each method is a module with a stable id and a `fit` that returns a `GrainFit` dict:

```text
id: "mppca" | "kmeans" | "agglomerative"
assignment: "soft" | "hard"
supports_split: bool          # True only for mppca
supports_dendrogram: bool     # True only for agglomerative
fit(X, params) -> GrainFit
  R : (n, k) float
  means : (k, d) L2-normalised (responsibility-weighted or cluster mean)
  labels : (n,) MAP
  extras : method-specific (component_fits | kmeans_inertia | children_/distances_)
figure_map(X, fit, phrases) -> {key: plotly spec}
```

Dispatch is one Assess compute, `subject_grain_fit`, switching on `cluster_method` from the parameters store. `subject_grain_seed_fit` becomes an MPPCA-shaped wrapper (`k=1`, `force_refit`) that calls `subject_grain_fit`, so existing 03_grain YAML keeps working until configs opt into the method dropdown.

`subject_grain_propose_split` / confirm / undo stay in the MPPCA module. YAML `visible_if` shows them only when `cluster_method` is `mppca`. Calling them on a hard \(R\) is an error, not a silent k-means split.

### sklearn methods

**K-means** (`sklearn.cluster.KMeans`, already imported).

| Parameter | Default | Notes |
|---|---|---|
| `n_clusters` | 8 | Hard \(k\); not the MPPCA seed |
| `kmeans_init` | `k-means++` | sklearn `init` |
| `kmeans_n_init` | 10 | sklearn default; MPPCA currently uses 1 for speed |
| `kmeans_max_iter` | 300 | |
| `seed` | 0 | `random_state` |

Fit on the embedding matrix after `_as_embedding_matrix` (the helper already in `mppca.py` should move with the catalogue / shared numeric helpers). One-hot \(R\) from `labels_`. Means = sklearn `cluster_centers_`, then L2-normalise for cosine consumers (distance ground cost).

Do not use `MiniBatchKMeans` in v1. Draghi-scale \(n \approx 1028\), \(d = 3072\) is in-core.

**Agglomerative** (`sklearn.cluster.AgglomerativeClustering`). sklearn ≥ 1.3 uses `metric=` (not `affinity=`).

| Parameter | Default | Notes |
|---|---|---|
| `n_clusters` | 8 | Same field as k-means (one \(k\) for hard methods) |
| `agglo_linkage` | `ward` | `ward` / `complete` / `average` / `single` |
| `agglo_metric` | `euclidean` | Ward **requires** Euclidean. For `average`/`complete`/`single`, `cosine` is allowed and natural on L2 embeddings |
| `seed` | unused by sklearn agglomerative | Keep on the parameters store for the other methods |

Set `compute_distances=True` so `distances_` is populated. Dendrogram JSON is built from `children_` and `distances_` (standard conversion to a scipy-style linkage matrix; no extra clustering library). v1 does **not** expose `distance_threshold` as an alternative to \(k\); one \(k\) keeps the catalogue shape identical to k-means.

If `agglo_linkage == ward` and `agglo_metric != euclidean`, fail in compute with an explicit error (sklearn would too; we fail before the estimator).

**Recommended first settings on L2 embeddings** (parameters.yml comments, not hidden code): k-means Euclidean; agglomerative `average` + `cosine`, or `ward` + `euclidean` if the analyst wants variance-minimising joins.

### Figures

| Method | Viewer figure | Stored as |
|---|---|---|
| mppca | existing local \(U_q\) per topic + pending-split overlay | `uq_by_topic` / `uq_spec` (names stay for compatibility) |
| kmeans | 2-D PCA of \(X\), colour = MAP cluster, click → `selected_phrase` | same fields, different spec |
| agglomerative | same PCA scatter, plus an optional dendrogram panel | PCA in `uq_spec`; dendrogram as a second Plotly field or a section under review |

Do not project k-means points onto an MPPCA \(U_q\). PCA is `sklearn.decomposition.PCA(n_components=2)` on \(X\) (or a truncated SVD; same stack as the MPPCA randomised SVD helper). Phrase click bindings stay `customdata.phrase`.

CIP-0012's later move to store plane parameters instead of Plotly JSON remains MPPCA-only follow-on work.

### Parameters store (not cache, not scores)

```yaml
# parameters.yml — writable grain knobs
cluster_method: mppca          # mppca | kmeans | agglomerative
n_clusters: 8                  # hard methods only
kmeans_init: k-means++
kmeans_n_init: 10
kmeans_max_iter: 300
agglo_linkage: average
agglo_metric: cosine
seed: 0
# existing MPPCA / naming knobs unchanged:
# sigma2, sigma2_mode, em_accept, em_preview, n_exemplars, label_*
```

03_grain review: a **Grain method** section with the dropdown and the hard-method knobs. MPPCA EM section `visible_if` method is mppca. K-means / agglomerative knobs `visible_if` their method. Changing `cluster_method` or `n_clusters` does not by itself rewrite \(R\); a **Fit** PopulateButton (or Reset) calls `subject_grain_fit` with `force_refit: true` and clears `pending_proposal`.

### Module layout

```
referia/assess/compute/
  grain_catalogue.py     # topic_keys, tree, one-hot R, parent maps, embedding stack
  grain_fit.py           # subject_grain_fit dispatch
  mppca.py               # mixture model + propose/confirm/undo (imports catalogue)
  kmeans.py              # sklearn KMeans → GrainFit
  agglomerative.py       # sklearn AgglomerativeClustering → GrainFit
referia/util/plotly_figures.py
  local_uq_plotly_spec           # unchanged, MPPCA
  cluster_pca_plotly_spec        # new, hard methods
  cluster_dendrogram_plotly_spec # new, agglomerative
```

v1 may keep files flat under `compute/` (match `distance.py`, `topic_naming.py`) rather than a package, to avoid a large import move in one PR. The **names and import graph** matter more than the folder: `kmeans.py` must not import `mppca_fit`; `mppca.py` may use `KMeans` only as mixture initialisation.

Shared numeric helper `_as_embedding_matrix` leaves `mppca.py` so k-means does not go through PPCA to stack object arrays.

### 03_grain Assess loop by method

| Action | mppca | kmeans | agglomerative |
|---|---|---|---|
| Fit / seed | \(k=1\) seed (existing) | fit `n_clusters` | fit `n_clusters` |
| Propose / Confirm / Undo | yes | hidden | hidden |
| Reset | \(k=1\) refit | refit current \(k\) | refit current \(k\) |
| Name | yes (uses \(R\)) | yes | yes |
| Focus dropdown | local plane swap | highlight cluster on PCA | highlight cluster / dendrogram cut |

### What this is not

| Nearby work | Difference |
|---|---|
| CIP-0012 model / figures / naming | Still true for MPPCA. This CIP adds a *method* axis. |
| CIP-0015 seed fit | Remains the MPPCA \(k=1\) path; dispatch wraps it. |
| sklearn GMM / Birch / HDBSCAN | Out of v1. The registry is how they would join later. |
| Soft k-means | Not requested. Hard one-hot \(R\) is the sklearn KMeans contract. |
| Replacing EMD | 04_distance unchanged. One-hot \(R\) → count histograms. |
| lynguine clustering | Application-layer compute. Stay in referia. |

### Risks

- **Comparing methods on the same scores.yml.** Switching method with `force_refit` replaces \(R\) and labels. Warn in the Fit button hint. Do not try to keep an MPPCA split tree under a k-means colouring.
- **Ward + cosine.** Must error, not fall through to sklearn's exception.
- **Agglomerative cost.** \(O(n^2 d)\) memory/time. Fine at \(n \approx 10^3\); document that \(n \gtrsim 10^4\) needs a different method.
- **Naming exemplars on one-hot \(R\).** `example_phrases_for_soft_topics` uses threshold \(1/k\). For one-hot, members have \(R=1\), so the cap `n_exemplars` still applies. No change required; add a test.

## Backward Compatibility

- Default `cluster_method: mppca` preserves the current 03_grain loop (k=1 seed, Propose / Confirm / Undo, \(U_q\)).
- Existing `subject_grain_seed_fit` / `subject_grain_propose_split` names stay registered.
- Scores files that already hold MPPCA \(R\) and `uq_*` keep loading. A k-means Fit overwrites those fields; that is opt-in.
- CIP-0016 distance configs do not change.

## Testing Strategy

- Catalogue helpers: one-hot from labels; tree Markdown with flat parents.
- K-means: \(n=20\), \(d=8\), \(k=3\); rows of \(R\) are one-hot; `n_clusters` matches \(R.shape[1]\).
- Agglomerative: same shape contract; invalid ward+cosine raises `ValueError` with linkage/metric in the message.
- Dispatch: `cluster_method="mppca"` still returns soft rows that sum to 1 and are not all {0,1} on a planted two-subspace mix (reuse existing MPPCA fixture).
- Propose on a k-means \(R\) raises (does not call `KMeans` again).
- Figure builders: PCA spec has `customdata.phrase`; dendrogram spec is Plotly JSON with \(n-1\) joins.
- No live sklearn version pin beyond `>= 1.3` (`metric=`).
