# CIP-0009: Template Expansion System for Referia Interfaces

## Summary

Implement a declarative template expansion system for Referia interface configurations that enables:
1. **Reusable widget patterns** through parameterized templates
2. **Nested template composition** for building complex interfaces from simpler components  
3. **Automatic column generation** from template-expanded fields
4. **Migration path** from legacy `CriterionComment` patterns to modern templates
5. **Standard template library** for common review and assessment patterns

This system reduces configuration duplication, improves maintainability, and provides a composable approach to building assessment interfaces.

## Motivation

### Current Problems

**1. Configuration Duplication**

Before templates, creating similar widget groups (e.g., for each thesis chapter) required extensive copy-paste:

```yaml
review:
  - type: Markdown
    liquid: "### Chapter 1"
  - type: Textarea
    field: "ch1Summary"
  - type: Textarea
    field: "ch1Comments"
  - type: Markdown
    liquid: "### Chapter 2"
  - type: Textarea
    field: "ch2Summary"
  - type: Textarea
    field: "ch2Comments"
  # ... repeat for 10+ chapters
```

**2. Legacy CriterionComment Patterns**

The system has hardcoded `CriterionComment*` types that programmatically expand to widget groups:

```yaml
scorer:
  - type: CriterionCommentScore
    criterion: "#### Overall"
    prefix: Overall
    min: 0
    max: 10
```

Problems with this approach:
- **Limited flexibility**: Fixed set of patterns in code
- **Hardcoded logic**: Expansion logic lives in `interface.py` rather than configuration
- **Not composable**: Cannot combine or nest these patterns
- **Maintenance burden**: Adding new patterns requires code changes

**3. No Composition**

Complex interface patterns cannot be built from simpler reusable components.

### Solution: Template Expansion System

Templates provide:
- **Parameter substitution** with `%param%` syntax
- **Recursive/nested composition** for building complex patterns
- **Auto-column generation** including timestamp suffixes
- **User-defined patterns** in configuration files
- **Standard library** of common templates
- **Migration path** from `CriterionComment` to templates

## Template Syntax

### Basic Structure

```yaml
templates:
  template_name:
    pattern:
      - type: WidgetType
        field: "%prefix%FieldName"
        args:
          description: "%label%"
```

### Parameter Substitution

**Syntax**: `%parameter_name%`

Parameters are replaced during template expansion:

```yaml
templates:
  comment_field:
    pattern:
      - type: Textarea
        field: "%prefix%Comment"
        args:
          description: "%label%"
          placeholder: "%placeholder_text%"

review:
  - template: comment_field
    instances:
      - prefix: "ch1"
        label: "Chapter 1"
        placeholder_text: "Enter comments..."
      - prefix: "ch2"
        label: "Chapter 2"
        placeholder_text: "Enter comments..."
```

**Expands to**:
```yaml
review:
  - type: Textarea
    field: "ch1Comment"
    args:
      description: "Chapter 1"
      placeholder: "Enter comments..."
  - type: Textarea
    field: "ch2Comment"
    args:
      description: "Chapter 2"
      placeholder: "Enter comments..."
```

### Escaping Literal Percent Signs

Use `%%` for literal `%` (following Windows batch convention):

```yaml
templates:
  progress_display:
    pattern:
      - type: Markdown
        liquid: "Progress: %value%%% complete"  # → "Progress: 95% complete"
```

### Interaction with Other Templating Systems

Referia uses three distinct templating syntaxes:

| Syntax | Purpose | Processed When | Example |
|--------|---------|----------------|---------|
| `%param%` | Template expansion parameters | Config load time | `%prefix%Summary` |
| `{{field}}` | Liquid data binding | Markdown rendering | `{{givenName}}` |
| `{Name}` | Display variable substitution | UI display time | `{Name}_thesis.pdf` |

These systems **do not interfere** with each other due to distinct delimiters.

## Nested Templates

### Single-Level Nesting

Templates can reference other templates:

```yaml
templates:
  # Base component
  text_with_button:
    pattern:
      - type: Textarea
        field: "%field_name%"
      - type: PopulateButton
        args:
          target: "%field_name%"
  
  # Higher-level template using the base
  section_review:
    pattern:
      - type: Markdown
        liquid: "### %title%"
      - template: text_with_button
        instances:
          - field_name: "%prefix%Summary"
```

### Multi-Level Nesting

Templates can nest arbitrarily deep (default max: 10 levels):

```yaml
templates:
  field:
    pattern:
      - type: Textarea
        field: "%name%"
  
  field_with_button:
    pattern:
      - template: field
        instances:
          - name: "%field_name%"
      - type: PopulateButton
        args:
          target: "%field_name%"
  
  section:
    pattern:
      - type: Markdown
        liquid: "### %title%"
      - template: field_with_button
        instances:
          - field_name: "%prefix%Summary"
```

### Circular Reference Detection

The system detects and prevents circular references:

```yaml
templates:
  template_a:
    pattern:
      - template: template_b
        instances: [{}]
  
  template_b:
    pattern:
      - template: template_a  # ❌ Error: Circular reference detected
        instances: [{}]
```

**Error**: `Circular template reference detected: template_a -> template_b -> template_a`

## Automatic Column Generation

### Problem

Without templates, users had to manually declare output columns including timestamp fields:

```yaml
output:
  columns:
    - ch1Summary
    - ch1Summary_modified
    - ch1Summary_created
    - ch1Comments
    - ch1Comments_modified
    - ch1Comments_created
    # ... repeat for all fields
```

### Solution

The system auto-generates columns from template-expanded fields:

1. Extract all `field` names from expanded `review` section
2. If `output.columns` doesn't exist, create it with extracted fields
3. For each field in `review`, add `_modified` and `_created` timestamp columns

```yaml
templates:
  chapter:
    pattern:
      - type: Textarea
        field: "%prefix%Summary"
      - type: Textarea
        field: "%prefix%Comments"

review:
  - template: chapter
    instances:
      - prefix: "ch1"
      - prefix: "ch2"

output:
  # columns: omit entirely - will be auto-generated as:
  # [ch1Summary, ch1Summary_modified, ch1Summary_created,
  #  ch1Comments, ch1Comments_modified, ch1Comments_created,
  #  ch2Summary, ch2Summary_modified, ch2Summary_created,
  #  ch2Comments, ch2Comments_modified, ch2Comments_created]
```

## Implementation Details

### Template Expansion Algorithm

```python
def _expand_templates_in_review(self, review, depth=0, max_depth=10, expansion_chain=None):
    """Recursively expand template references."""
    if depth > max_depth:
        raise ValueError(f"Maximum template nesting depth ({max_depth}) exceeded")
    
    expanded_review = []
    
    for entry in review:
        if isinstance(entry, dict) and 'template' in entry:
            template_name = entry['template']
            instances = entry.get('instances', [])
            
            # Check for circular reference
            if template_name in expansion_chain:
                raise ValueError(f"Circular template reference: {' -> '.join(expansion_chain + [template_name])}")
            
            # Expand each instance
            for instance in instances:
                expanded_entries = self._expand_template_instance(template_name, instance)
                
                # Recursively expand any nested templates
                nested_expanded = self._expand_templates_in_review(
                    expanded_entries,
                    depth=depth + 1,
                    max_depth=max_depth,
                    expansion_chain=expansion_chain + [template_name]
                )
                expanded_review.extend(nested_expanded)
        else:
            expanded_review.append(entry)
    
    return expanded_review
```

### Parameter Substitution

```python
def _substitute_parameters(self, obj, params, template_name=None):
    """Recursively substitute %param% placeholders."""
    if isinstance(obj, str):
        # Find all %param% placeholders
        placeholders = re.findall(r'%(\w+)%', obj)
        
        # Check for missing parameters
        for placeholder in placeholders:
            if placeholder not in params:
                raise ValueError(f"Parameter '%{placeholder}%' is required but not provided")
        
        # Substitute all parameters
        result = obj
        for param_name, param_value in params.items():
            result = result.replace(f"%{param_name}%", str(param_value))
        
        # Unescape %% to %
        result = result.replace('%%', '%')
        
        return result
    
    elif isinstance(obj, dict):
        return {
            self._substitute_parameters(k, params, template_name):
            self._substitute_parameters(v, params, template_name)
            for k, v in obj.items()
        }
    
    elif isinstance(obj, list):
        return [self._substitute_parameters(item, params, template_name) for item in obj]
    
    else:
        return obj
```

### Column Auto-Generation

```python
# In Interface.__init__, after template expansion:
for output_type in output_types:
    if output_type in data:
        # Create columns list if missing
        if "columns" not in data[output_type]:
            data[output_type]["columns"] = []
            for col in review_columns:  # Extracted from expanded review
                data[output_type]["columns"].append(col)
        
        # Add _modified and _created timestamp columns
        for column in data[output_type]["columns"]:
            if column in modified_columns:
                if modified_columns[column] not in data[output_type]["columns"]:
                    data[output_type]["columns"].append(modified_columns[column])
            if column in created_columns:
                if created_columns[column] not in data[output_type]["columns"]:
                    data[output_type]["columns"].append(created_columns[column])
```
