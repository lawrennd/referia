## Summary

The soft-topic Assess demo (`examples/subject_grain_uq`) and its compute
helpers shipped as a working loop, but the packaging mixed three concerns in
one place: the probabilistic PCA model, Plotly figure construction, and
LLM topic-naming prompts. This CIP records that debt and the target
separation so user-facing docs and modules describe behaviour, not process
history.

**Partial clean-up already on the branch:** figures moved to
`referia.util.plotly_figures`, naming helpers to
`referia.assess.compute.topic_naming`, default `label_prompt` lives in
`_referia.yml`, and the example README no longer narrates other repositories.

## Motivation

A single `mppca.py` grew into fit + EM + propose/confirm/undo + Plotly JSON +
prompt templates. That makes the model harder to test and reuse, and it
forces Assess configs to inherit packaging accidents (prompt defaults in
Python, CIP identifiers in registry docstrings). Visual updates belong with
other figure builders; naming copy belongs in the review config the steward
edits.

## Detailed Description

### Target layers

| Layer | Owns | Does not own |
|-------|------|----------------|
| **Model** (`mppca`) | Fit, responsibilities, propose-split maths, catalogue field updates that are pure state | Prompt strings, Plotly traces, CDN/widget chrome |
| **Figures** (`util.plotly_figures` or a future `util.plot` package) | Local \(U_q\) and proposed-split figure JSON from geometry | EM / fit |
| **Naming** (config + thin helpers) | `label_prompt` / `label_model` in `_referia.yml` / scores; fill / stub / parse helpers | Mixture likelihood |
| **Access bake** (follow-on) | Phrases + embeddings → `records.yml` | Soft fit (Assess seed is separate) |

`rebuild_uq_by_topic` and the propose/confirm/undo façade still call into
figure builders today — that glue should shrink so catalogue updates return
geometry (planes / covariances) and a thin Assess adapter (or the viewer
binding) asks for figures.

### Remaining work

1. Stop storing full Plotly specs as the primary Assess artefact if possible —
   store plane parameters (μ, \(U_q\), scales / cov) and rebuild figures in the
   viewer path (or a dedicated `figure_source` compute). That separates
   “model updated” from “widget redraw”.
2. Move or delete leftover façade comments that describe UI chrome inside the
   model module.
3. Replace `build_records.py` with an explicit Access → Assess seed path
   (see backlog `2026-10-19_cip0017-lynguine-access-bake`; retarget to this CIP).
4. Keep interactive bindings (click / `figure_source`) under the viewer stack
   already introduced for typed Plotly figures — do not grow more Plotly
   knowledge inside `mppca`.

### Non-goals

- Changing the Assess UX of Propose / Confirm / Undo.
- Replacing soft responsibilities with hard labels as primary state.

## Implementation Plan

1. **Document and freeze the working demo** (this PR): README, config-owned
   prompt, figure/naming module split, CIP-free user docs.
2. **Accept this CIP** → backlog tasks for plane-parameter storage vs figure
   rebuild, and for lynguine Access bake.
3. **Implement** figure rebuild from plane parameters; slim `mppca` to model +
   catalogue scalars / arrays.
4. **Validate** tests + manual subject_grain_uq loop; close CIP; compress into
   Sphinx / package docs if needed.

## Backward Compatibility

Example scores that already embed Plotly JSON remain readable. A later move
to plane-parameter storage needs a one-shot re-bake of `scores.yml` (already
gitignored) and possibly a version bump on the example config.

## Testing Strategy

- Manual: `examples/subject_grain_uq` Propose → Confirm / Undo; Name focus
  topic with stub and with a live model when keyed.
