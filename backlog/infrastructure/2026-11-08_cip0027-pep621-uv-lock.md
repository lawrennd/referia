# Task: Convert pyproject.toml to PEP 621 and generate uv.lock

> Backlog tasks are DOING the work defined in CIPs (HOW).  
> Implements CIP-0027.

## Description

Replace Poetry-specific packaging metadata with PEP 621 so uv can own the developer lock/install path.

- Move `[tool.poetry]` package metadata to `[project]`
- Move runtime deps (git lynguine, spaCy URL model, Darwin markers) to PEP 621 / `[tool.uv.sources]`
- Map extras `llm` / `distance` to `[project.optional-dependencies]`; drop duplicate Poetry `llm` group
- Map docs / pytest-style deps to `[dependency-groups]`
- Move `referia` console script to `[project.scripts]`
- Switch build backend to hatchling; preserve `defaults.yml` and web static/templates
- Run `uv lock`, commit `uv.lock`, remove `poetry.lock`

## Acceptance Criteria

- [x] `pyproject.toml` uses PEP 621 `[project]` (no `[tool.poetry]` packaging tables required for install/build)
- [x] Optional extras `llm` and `distance` install via standard extras / `uv sync --extra …`
- [x] `dev` and `docs` dependency groups are defined and usable with uv
- [x] `referia` remains an installed console script
- [x] Git lynguine, spaCy URL, and Darwin markers resolve under `uv lock`
- [x] `uv.lock` is committed; `poetry.lock` is removed
- [x] Local `uv sync --extra llm --group dev` succeeds
- [x] `uv run pytest` (or a focused smoke) and `uv run referia --help` succeed

## Implementation Notes

Prefer `[tool.uv.sources]` for the git lynguine pin so extras stay in the dependency string as `lynguine[documents,parquet]`.
